## 二、项目目的与架构（定调，不可偏离）

这是整个项目最核心的思路，任何实现都要符合它：

- **dsh 人设项目（dsh-soul / dsh-fish-soul 等）→ 只出「人设」**（name + 正文），fish-body 通过 `PersonaSource` 接口「原生导入」。
- **pet 项目 → 只出「动画」**（webm / layered png / live2d），作为人设的表现形式。
- **fish-body（本项目）→ 桌宠展示层**：把人设 + 动画汇合，用动画来展示人设。

推论（务必遵守）：
1. **人设与动画是正交的两条轴**：人设同步（`persona-source`）和渲染后端（`render`）互不耦合。换动画包不改人设，换人设不改动画包。
2. 人设卡是「导入」语义：卡里的 `name` 要覆盖宠物的 `name`（已实现），正文覆盖 `whisperPrompt`。
3. 动画包（webm/layered/live2d）三者**互斥**，用户右键切换「渲染方式」作常态。

## 五、P2 渲染层：完整设计思路（当前阶段核心）

### 5.1 目标

渲染层支持 `webm / layered png / live2d` 三种，互斥；用户在**桌宠右键菜单**选「渲染方式」作常态；右键菜单内容随渲染方式不同；后续接人设心情（webm 按心情换文件，layered/live2d 按心情做动作）。**耗电优先**：layered 纯 canvas 按需重绘、live2d 复用 Cubism 帧、webm 空闲暂停视频。

### 5.2 已落地的地基（T2.1）

- `src/shared/types.ts`：`RendererKind = 'webm' | 'layered' | 'live2d'`；`Pet.renderer?: RendererKind`（缺省 webm）。
- `src/host/config/`：`RENDERER_SET`（白名单）、`mergePet` 填默认 `webm`、`saveUserConfig` 白名单写回；默认配置 `assets/config.jsonc` 显式 `"renderer": "webm"`。
- `src/client/pet/render/types.ts`：`Renderer` 接口 + `RendererMountOptions` + `RendererFactory`。
- `src/client/pet/render/registry.ts`：`registerRenderer(kind, factory)`（工厂语义，每卡造一实例）/ `createRenderer(kind)` / `listRenderers()` / `resetRenderers()`。

### 5.3 `Renderer` 接口（契约，读 `src/client/pet/render/types.ts`）

```ts
interface Renderer {
  readonly kind: RendererKind;
  mount(stage: HTMLElement, opts: { size: number; assetRoot: string }): void | Promise<void>;
  destroy(): void;
  playAction(name: string, opts?: { once?: boolean }): void;   // 一次播完
  setIdle(name: string): void;
  setMouth?(open: number): void;        // 口型，layered/live2d 支持，webm 可不实现
  setGaze?(x: number, y: number): void; // 视线，同上
  setMood?(mood: string): void;         // 心情（后续），webm 换文件 / layered/live2d 做动作
  hitTest?(x: number, y: number): string | undefined; // 命中区，layered/live2d 支持
  readonly ready: boolean;
}
```

**关键分层（不可偏离）**：`Renderer` 只管「视觉 + 动作播放」；**交互与运动**（拖拽/走位/抛掷/挤压/菜单/状态/点击）留在卡片层。不要让交互逻辑漏进 Renderer。

### 5.4 下一步 T2.2：webm 适配器（本阶段最难的一块）

现状：现有渲染是**视频双缓冲、深度耦合在 `src/client/pet/card/`** 里——`animation.ts`（`OwnAnimation`：videoA/videoB 交叉淡入淡出、世代号、cue、ended 回调）、`pet-card.ts`→`view.ts`+`runtime.ts`（DOM 装配）、`state.ts`（卡状态）、`live.ts`（运动/拖拽/挤压的迟绑槽）。

重构目标：把「视频 A/B + 交叉淡入淡出 + 动作/待机切换 + 播放进度上报」抽成 `webm` Renderer；卡片层只保留运动/拖拽/挤压/菜单/状态，通过 `renderer.playAction()/setIdle()` 驱动视觉。

具体落点建议：
1. 在 `src/client/pet/render/webm.ts` 建 `createWebmRenderer()`，内部搬运 `OwnAnimation` 的视频播放逻辑（A/B 双缓冲、淡入淡出、ended）。
2. 卡片的 `animation.ts` 从「自己持有 video 元素」改为「持有 renderer 实例」，把 `switchTo` 映射成 `renderer.playAction/setIdle`。
3. `mount` 时由 `pets[].renderer` 决定：`createRenderer(kind)`，未注册/失败回退 `webm`；切 renderer 时 `destroy()` 旧的、`mount()` 新的（stage 即时重建）。
4. 进度上报（`registerProgress`）目前读 `ownAnim.frontVideo()`，要改成经 renderer 暴露当前播放状态。

验收：右键菜单能切「渲染方式」且 webm 一条线正常播放；切到未实现的 layered/live2d 时明确提示（不崩、不静默黑屏）。

### 5.5 后续里程碑

- **T2.3 layered**：移植 `legacy:assets/layered.js`（28KB，已验证 66fps + 命中区 + 口型）→ TS，做 `layered` Renderer；皮肤扫描（`D:\AI\FishChi\body\skins` 5 套 surfcore 皮肤，`manifest.json` + 分层 PNG）。
