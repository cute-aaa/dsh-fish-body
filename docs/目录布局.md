# 目录布局

这份文档是**数据根布局的唯一权威说明**：磁盘上有什么、每个目录归谁、升级时怎么搬、缓存与运行时有什么区别、
位置怎么改。设置页「系统 → 文件与目录」显示的就是这里的第一张树，两者必须同步改。

## 1. 一棵树

```
fish-body/                         数据根；默认 $DSH_HOME/fish-body（位置可改，见 §4）
├─ config/
│  ├─ main-config.jsonc            你的主配置（可手改；legacy main-config.json 只读回落 + 启动迁移）
│  ├─ session-fish.json            会话鱼设置（整份重写，不碰主配置的注释）
│  ├─ voice-providers.json         本地语音接入
│  └─ locations.json               位置指针（皮肤目录 / 运行时目录，见 §4）
├─ data/
│  ├─ memory.json                  对话记忆（按宠物分桶）
│  └─ todos.json                   待办
├─ cache/
│  ├─ voice/                       语音合成结果（一句一个音频文件）
│  ├─ download/                    Electron 安装包与 SHASUMS 缓存
│  └─ desktop/                     桌面窗口的 Chromium profile（位置 / 缩放）
├─ runtime/
│  └─ electron/                    Electron 运行时（默认位置；可用 locations.json 指到别处）
├─ skin/                           用户皮肤：<名>-config.json + <名>-animation/ -sound/ -memes/ -skin/
├─ assets/
│  ├─ animation/{webm,mov}/        main 的动画（文件名即动作名）
│  ├─ sound/                       用户级音效（无前缀文件名对所有宠物生效）
│  ├─ memes/                       用户级表情包
│  ├─ pet/                         内置皮肤池（assets.pool 的默认值；layered / live2d / webm / sound）
│  └─ session-fish/                会话鱼皮肤
└─ logs.txt                        统一日志（1 MB 上限，写满只留最新 512 KB）
```

界面里第一行是目录名（`fish-body/`）而不是 `<数据根>/`：树根顶格、不画枝干，第一层子项直接从第 0 列开始，
所以名字本身就得是「这是哪个目录」。`├─`/`└─` 由客户端按 `depth` 画（见 `client/settings/tree`），
宿主只给扁平结构与顺序。

包内（只读，改动随升级丢失）：

```
<插件包>/assets/config.jsonc        内置默认配置（完整示例）
<插件包>/assets/sound|memes/        随包素材
<插件包>/runtime/electron-helper/   桌面窗口的 Electron 入口
```

## 2. 命名为什么是这样

`pet` 与 `skin` 在上一版是反的，这一版按「谁的素材」分清：

| 目录              | 归属                     | 含义                                                   |
| ----------------- | ------------------------ | ------------------------------------------------------ |
| `assets/pet/`     | 插件共用的**内置皮肤池** | 所有宠物共用一份；`assets.pool` 可改到任意路径         |
| `skin/`           | **用户自己的皮肤**       | 一个 pack 一套 `<名>-*` 文件与目录，可整体搬走、可备份 |
| `skin/<名>-skin/` | 某个 pack 自己的素材     | 解析时**先 pack 后池**：pack 自带优先，池只做补充      |

旧版正好相反（`pets/` 放用户皮肤、`assets/skin/` 放池）。`assets.pool` 里残留的旧默认值
（`skin` / `assets/skin`）会按默认处理并归一到 `assets/pet`——那是我们自己写进用户配置的，
不该在升级后变成「皮肤全没了」。

## 3. 缓存与运行时

分开放，因为它们的「价值」不同：

- `cache/` 存的是**可重新生成的结果**：语音合成音频、安装包、窗口 profile。清掉只影响下一次的速度
  与窗口记忆，不影响任何设置。
- `runtime/` 存的是**可执行文件**：Electron 本体（约 350 MB）。它跟 cache 分开，所以清 cache 不会逼
  用户重下；反过来它也不该被当成缓存随手清掉。

措辞上刻意**不写「可以删 / 删了没影响」**：语音缓存在断网时可复用、安装包缓存在镜像抽风时能救急，
一句话断言在真实场景里经常不成立。界面上只描述「这个目录存什么」，由用户自己判断。

## 4. 位置可改

| 想改什么        | 记在哪                                                          | 缺省                        | 生效方式         |
| --------------- | --------------------------------------------------------------- | --------------------------- | ---------------- |
| 数据根          | `$DSH_HOME/fish-body-root.json` → `{ schema, root, movedAt }`   | `$DSH_HOME/fish-body`       | 重启插件         |
| 用户皮肤目录    | `<数据根>/config/locations.json` 的 `skin`                      | `<数据根>/skin`             | 重启插件         |
| Electron 运行时 | 同文件的 `runtime`；或 `POST /desktop/runtime { action:"dir" }` | `<数据根>/runtime/electron` | 桌面窗口自动重建 |

优先级：环境变量 `DSH_PET_USER_ROOT` > 指针文件 > 缺省。指针指向的目录不存在 → 回落到缺省位置并记一条
warn（「换盘后没挂载」不该变成一次空数据启动）。

搬动流程（`POST /layout/location`，界面在「文件与目录」卡里）：

0. 点「更改位置…」先进**说明步**：拿 `GET /layout/size?which=root|skin` 数出当前位置有多少文件与字节，
   把「会整体迁移、旧位置会被移除、失败时两处都保留」讲清楚，再让用户去选目录；
   选好之后还有一次确认弹窗，把「旧 → 新」两条路径并排摆出来；
1. 先算源目录的总字节与文件数（进度条的分母，与说明步同一套 `dirSize`）；
2. 逐文件复制（250ms 节流上报进度）；
3. 核对目标：文件数与字节数都必须与源一致；
4. **核对通过才删旧位置**；核对不上、或复制中途出错 → 两份都保留，错误原样回给界面。

界面不乐观更新路径：搬完只置 `needsRestart`，由用户点「立即重启」（`POST /plugin-restart`）。
进程内不热切路径——日志文件、store、路由依赖都在装配期绑在旧根上，半路换根会得到「一半读旧、一半写新」。

## 5. 升级迁移（`host/migrate-layout`）

硬约束：**绝不覆盖、绝不删除源**。目标已存在 → 跳过并 warn；单条失败 → 记下继续下一条（下次启动接着搬）。
回执写在 `<数据根>/.layout.json`，`node scripts/migrate-layout.mjs --revert` 可反向搬回。

| 旧位置                                                                       | 新位置                                                  | 说明                                                                                              |
| ---------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `main-config.jsonc` / `.json` / `session-fish.json` / `voice-providers.json` | `config/`                                               | 文件先搬，后面目录搬不动也不影响配置能读                                                          |
| `memory.json` / `todos.json`                                                 | `data/`                                                 |                                                                                                   |
| `main-animation` / `main-sound` / `memes` / `session-fish-skin`              | `assets/animation` `/ sound` `/ memes` `/ session-fish` |                                                                                                   |
| `skin/`（**旧布局的池**）                                                    | `assets/pet/`                                           | **带结构守门**：只有「长得像池」才搬（有 `layered/live2d/webm/sound` 且顶层没有 `*-config.json`） |
| `assets/skin/`（上一版的池）                                                 | `assets/pet/`                                           | 路径唯一，直接改名                                                                                |
| `pet/`（dsh-pet 时代单宠）                                                   | `skin/`                                                 |                                                                                                   |
| `pets/`（上一版的用户皮肤）                                                  | `skin/`                                                 |                                                                                                   |
| `voice-cache`                                                                | `cache/voice`                                           |                                                                                                   |
| `electron`                                                                   | `runtime/electron`                                      | 运行时跟缓存分开                                                                                  |
| `$DSH_HOME/electron`                                                         | `<数据根>/runtime/electron`                             | 数据根之外的一次性搬迁，源保留                                                                    |
| `dsh-pet/`（整个旧根）                                                       | `fish-body/`                                            | 换名失败（进程占用 / EPERM）→ 递归复制，旧根保留                                                  |

顺序不能换：**池先搬（带守门）、皮肤后搬**。反过来执行时 `<根>/skin` 会被当成另一种含义搬错，
用户就再也找不到自己的皮肤了。

## 6. 谁在读这份布局

- 路径字面量只在 `src/host/user-layout.ts`：别的模块一律通过 `UserPaths` 取值，禁止自己 `join(root, …)`。
- 位置指针在 `src/host/locations.ts`（读写 `locations.json` 与根指针，含优先级解析）。
- 搬迁在 `src/host/move-tree.ts`；原生目录选择在 `src/host/pick-folder.ts`。
- 设置页的树由 `src/host/routes/config/meta-layout.ts` 摊平成 `{ key, depth, … }`，客户端只画 `├─/└─`
  并按 `key` 取一句说明（`src/client/settings/tree-notes.ts`）。
- 目录备注（Windows `desktop.ini` 的 `InfoTip`）在 `src/host/user-layout.ts` 的 `LAYOUT_NOTES`：
  只写中文、只描述「存什么」，因为它跟着目录走、不跟界面语言走。
