# 资源目录重构方案（A 方案：双布局，池根 `skin/`）

## 1. 目录规范

```
<userRoot>/                          # 例如 D:\NodeJs\DSH_home\dsh-pet\
├─ pet/                              # 【旧】按 pack 分，保持原样，零迁移
│  ├─ main-skin/character1/…         # pack 私有皮肤（layered / live2d）
│  ├─ main-animation/webm/…          # pack 私有动画
│  ├─ main-sound/…                   # pack 私有音效
│  └─ feiyu-01-skin/……
├─ main-sound/                       # 【旧】用户级全局音效
└─ skin/                             # 【新】共享资源池（本方案的池根）
   ├─ layered/
   │  ├─ character1/
   │  │  ├─ xxx.json                 # 结构文件（任意名；manifest.json 优先）
   │  │  ├─ audio/…                  # json 内部引用的其他文件（发现时跳过）
   │  │  ├─ xxx-click.wav
   │  │  └─ character1-drag.wav
   │  ├─ character2/
   │  └─ sound/                      # 该渲染方式兜底
   │     ├─ layered-click.wav
   │     └─ layered-drag.wav
   ├─ live2d/
   │  ├─ model1/
   │  │  ├─ xx.model3.json
   │  │  ├─ xx/…                     # 模型资源
   │  │  └─ xx-click.wav
   │  ├─ model2/
   │  └─ sound/
   │     └─ live2d-click.wav
   ├─ webm/                          # 平铺，不是每资源一目录
   │  ├─ movie1.webm
   │  ├─ movie1-click.wav
   │  ├─ movie2.webm
   │  └─ webm-click.wav              # 该渲染方式兜底（平铺，无 sound/ 子目录）
   └─ sound/                         # 全局音效
      ├─ click.wav                   # 无前缀，优先
      └─ common-drag.wav             # 任意前缀，次之
```

**保留字**：`pool` 是池在 URL / 配置里的虚拟素材根，**不能作为 pack 名**（校验时拒绝）。

## 2. 资源发现规则

| 目录 | 什么算一个资源 | id（`model` 写什么） | 结构文件判定 |
| --- | --- | --- | --- |
| `skin/layered/` | 一级子目录 | 目录名，如 `character1` | `manifest.json` > 含 `"rig"/"schema"` 的 `.json` > 唯一的 `.json`；都没有则跳过并告警 |
| `skin/live2d/` | 一级子目录 | `.model3.json` 的相对路径，如 `model1/xx.model3.json` | 目录内第一个 `*.model3.json` |
| `skin/webm/` | `*.webm` 文件 | 基名，如 `movie1`（与 `animations` 池一致） | — |
| `skin/sound/` | 全局音效，不枚举为资源 | — | — |
| `skin/<T>/sound/` | 该渲染方式兜底，不枚举 | — | — |

不可见/跳过的：`audio/` 等子目录、`.` 开头、非白名单扩展名。所有路径都过 `resolve` + 池根内校验，禁止 `..` 逃逸。

## 3. 音效查找链（唯一真源）

对事件 `E`、渲染方式 `T`、资源目录 `D`、结构文件基名 `S`：

| # | 路径 | 来源标签 `origin` |
| --- | --- | --- |
| 0 | 显式配置：`manifest.sfx` / `sfx` 段 / `sfx.hooks` | `config` |
| 1 | `D/S-E.ext` | `pool-skin`（文件名级） |
| 2 | `D/<D 的目录名>-E.ext` | `pool-skin`（目录名级） |
| 3 | `T/sound/T-E.ext`（webm 特例：`webm/T-E.ext`，也兼容 `webm/sound/T-E.ext`） | `pool-renderer` |
| 4 | `skin/sound/E.ext` → `skin/sound/<任意前缀>-E.ext` | `pool-global` |
| 5 | 旧布局：`pet/<pack>-skin/<model>/E.ext`（皮肤目录内） | `skin` |
| 6 | 旧布局：`pet/<pack>-sound/<model>-E.ext` → `<E.ext>` | `sound` |
| 7 | 旧布局：动画同目录 `<动画名>-E.ext` | `animation` |
| 8 | 旧全局 `<userRoot>/main-sound/E.ext` | `user` |
| 9 | 包内 `assets/sound/` | `package-default` |
| 10 | 内置默认文件名 | `package-default` |

-   每级内扩展名优先 `.wav > .ogg > .mp3 > .m4a`；事件名规范化 `click drag throw floor wall ceiling pet sleep-start|sleepStart sleep-end|sleepEnd`。
-   `skin/sound/` 同事件出现多份时：**无前缀优先**，其次文件名排序取第一并告警一次。
-   `hook-<名>.wav` 走独立通道（第 1/3/4/5 级都可命中），不掺进事件链。
-   `webm` 无资源目录，所以第 2 级跳过；若将来把一部电影做成目录（`webm/movie1/movie1.webm`），第 1/2 级自然生效，规则不变。
-   索引缓存键沿用现有的 `assetRoot|renderer|model`，池资源固定 `assetRoot = "pool"`。

## 4. 配置与接口契约

**新增 `assets` 段（全局）**

```
jsonc
"assets": {
  "pool": "skin"   // 相对用户根，或绝对路径；默认就是 "skin"
}
```

**宠物条目**：`renderer` + `model` 语义扩展，**先 pack 后池**：

| renderer | model 解析顺序 |
| --- | --- |
| `layered` | `pet/<pack>-skin/<model>/`（旧） → `skin/layered/<model>/`（池） |
| `live2d` | `pet/<pack>-skin/<model 所在目录>`（旧） → `skin/live2d/<model>`（池） |
| `webm` | `model` 不参与；动画池由 `animations` 配置按基名引用，先 `pet/<pack>-animation/webm/` 后 `skin/webm/` |

**URL**：池作为虚拟素材根 `pool`

-   `GET /sound/pool/<file>?model=<模型>`、`GET /sound/pool/index?renderer=&model=`
-   `GET /thumb/pool/…`、`GET /animations/pool/…` 同理（与现有 `assetRoot` 段等价，只是解析分支不同）
-   桌面 helper 与网页客户端都只认 `assetRoot="pool"`，不各自拼路径

**`open-folder`**：`which` 增加 `pool-layered | pool-live2d | pool-webm | pool-sound | pool-global-sound`，返回算好的目录（不存在则回 `path`，前端照既有气泡问"是否创建"）。

## 6. 客户端 / 桌面改动

-   **共享**：`shared/sfx/*` 的解析器不认路径，只认索引与覆盖层——只需透传新 `origin` 文案。
-   **网页**：`client/pet/sfx.ts` 里 `sfxUrl` 对 `assetRoot='pool'` 不特殊处理（`/sound/pool/...` 直接用）；`loadSfxIndex` 的缓存键已含 model。
-   **桌面 helper**：`constants.js` 的 `soundUrlOf(assetRoot, …)` 已拼 `/sound/<root>/…`，`root=pool` 天然可用；`sprite.js` 的 `sfxPlan()` 不变。
-   **设置页**：
    -   音效卡每行第二行显示**实际命中路径**；未命中时显示"建议放这里：`skin/layered/character1/character1-click.wav`"，并配「打开文件夹」。
    -   模型选择器来源标注 `池` / `pack`。
    -   新增一段只读目录说明（池根当前解析结果）。

## 7. 兼容 / 冲突 / 迁移

-   **旧布局零迁移**：`pet/<pack>-skin|sound|animation` 完全不动，查找链第 5–8 级原样保留。
-   **同名冲突**：先 pack 后池（§4），设置页标注来源；音效链里池优先于旧全局（用户新放的东西先响）。
-   **`skin/` 不存在**：视为空池，不报错、不告警（用户没启用新布局）。
-   **可选迁移脚本**（后续阶段，不在本轮）：把 `pet/x-skin/<子目录>` 搬到 `skin/<renderer>/<子目录>`，把 `-animation/webm/*.webm` 搬到 `skin/webm/`，把 `main-sound` 搬到 `skin/sound/`；只搬不删，输出清单。

## 8. 分阶段实施与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **1** | 池扫描 + 四级查找链 + 索引（§2–3） | 放 `skin/layered/character1/xxx.json` + `xxx-click.wav`，`GET /sound/pool/index?renderer=layered&model=character1` 的 `events.click` = `xxx-click.wav`，`GET /sound/pool/xxx-click.wav` → 200 |
| **2** | 选择与加载（`/config` 清单、model 解析、`/thumb` `/animations` 池根、桌面 helper） | 设置页能选到 `character1`；网页与桌面都能加载；webm 动画从 `skin/webm/` 播放 |
| **3** | 「放哪儿」引导（实际路径 + 建议路径 + 打开文件夹 + 创建确认） | 音效卡每行能看到/打开对应目录，用户照提示放文件后刷新即生效 |
| **4** | 文档（MAKE-YOUR-OWN-PET 换成这套图、CONFIG 增 `assets` 段）+ 迁移脚本 + openapi | 文档与接口一致；迁移脚本干跑输出清单 |

## 9. 风险与刻意不做的事

-   **不做**：把旧布局改成新池的唯一形态（A 方案明确保留旧布局）；把 `webm/` 改成每资源一目录（平铺是它的自然形态，规则已特例处理）；全局层前缀做语义（`common-` 只是名字，不解析含义）。
-   **风险点**：layered 结构文件命名不统一 → 发现规则必须容错并告警一次；`pool` 假名与 pack 名冲突 → 校验拦截；两端 bundle（client / desktop runtime）都要重建，`shared` 保持单一真源。
-   **性能**：池扫描只在宿主装配与索引请求时做，不做文件监听；同一请求内复用扫描结果。
