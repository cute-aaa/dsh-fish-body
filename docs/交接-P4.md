## 一、一句话现状

桌宠现在会**看一眼屏幕说一句话**（默认关），也会在**你全屏打游戏 / 打开白名单里的程序时自己躲起来**
（默认关）。两件事的**开关与时机全部可配**：十三个键在配置里、在设置页「系统 → 看屏幕与避让」里，
也都经由 `PUT /config` 落盘。

P4 的四条链路：

| 环节 | 位置 | 一句话 |
|---|---|---|
| 取帧 | `runtime/electron-helper/main/capture.js` | 物理像素取图 → 判黑图 → 缩到长边 1280 → JPEG |
| 节奏 | `host/screen/policy.ts` + `routes/screen.ts` | Helper 每 5s 问 `GET /screen/tick`，宿主按十三项回答 |
| 说一句 | `host/vision.ts` + `host/broadcast-send.ts` | 读图 → 一句话 → 写 `say` 叶子（只出气泡、不念） |
| 躲开 | `shared/avoid.ts` + `main/foreground.js` + `sprite/avoid.js` | PowerShell 问前台窗口 → 滞回状态机 → hide/showInactive |

## 三、十三个配置键（唯一事实表）

平的键写在配置顶层（`assets/config.jsonc` 与用户层 `main-config.jsonc` 同层），
拍平时收成嵌套的 `pet.screen`（`shared/config.ts` 的 `flattenConfigPets`）。

| 键 | 类型 | 默认 | 区间 / 规则 | 作用 |
|---|---|---|---|---|
| `screenReadEnabled` | bool | `false` | — | 识屏总开关 |
| `screenReadIntervalSec` | number | `120` | 30–3600 | 两句最短间隔（费用上限） |
| `screenReadIdleOnly` | bool | `true` | — | 只在 DSH 空闲时拍 |
| `screenReadIdleSec` | number | `30` | 0–600 | 空闲判定阈值（距上次会话事件） |
| `screenReadQuietFrom` / `screenReadQuietTo` | string | `''` / `''` | `HH:MM`，空串=不设，允许跨午夜 | 静默时段 |
| `avoidFullscreenEnabled` | bool | `false` | — | 全屏前台时躲开 |
| `avoidMaximizeEnabled` | bool | `false` | — | 最大化（任务栏可见）也算触发 |
| `avoidDelayMs` | number | `1500` | 0–10000 | 覆盖持续多久才躲 |
| `avoidRestoreDelayMs` | number | `800` | 0–10000 | 条件消失后多久回来 |
| `avoidPollMs` | number | `800` | 300–5000 | 前台轮询节拍 |
| `avoidAppsEnabled` | bool | `false` | — | 白名单程序前台时躲开 |
| `avoidApps` | string[] | `[]` | ≤50 条、每条 ≤64 字、大小写去重 | `.exe` 结尾按进程名精确比，否则按窗口标题子串 |

**运行期夹取、写盘拒绝**：`shared/screen-config.ts` 的 `screenConfigOf` 对越界值夹到边界（跑得下去），
`host/config/screen-keys.ts` 的 `screenPatchOf` 对越界值整包拒绝（不替用户猜）。这两条不要合并。

## 四、数据链（按顺序读这一节就能改）

### 4.1 识屏

1. Helper 渲染端 `sprite/screen.js`：`startScreenWatch(pet)` 只在 `pet.screen.readEnabled === true` 时启动，
   每 **5 秒** `GET /screen/tick?pet=<id>`（开关关着时一条请求都不发）。
2. 宿主 `routes/screen.ts` 的 `screen/tick`：`screenConfigOf(who.conf)` +
   `agentIdleForMs()`（`host/agent-activity.ts`，由 `session-watch` 的 `session/event` 监听刷新）+
   静默时段 + 间隔，交给 `decideScreenTick()`。判定顺序：`disabled → manual → throttled → busy → quiet → ready`。
   手动请求**只有真的拍下去**才被消费。
3. `capture:true` → `window.petBridge.captureScreenFrame()` → 主进程 `main/ipc.js` 的 `pet:screen-frame`
   → `main/capture.js` 的 `grabScreen({maxEdge:1280, quality:80, checkBlack:true})`。
4. 黑图（32×32 网格，非黑采样点 <0.2%）→ **不上传**，渲染端改用 `getDisplayMedia` 兜底
   （主进程在 `whenReady` 里注册了 `setDisplayMediaRequestHandler`，自动选第一块屏）。
5. `POST /screen/frame?pet=` → `admitPetImage()`（与 `/chat` 同一份准入，落进宿主附件服务）→
   `describeScreen()`（候选链：`whisperModel` → 当前对话模型）→ `sendSay()` 写 `say` 叶子。
6. 结果与失败都进 `host/screen/state.ts` 的 `last`，`GET /screen/state` 读得到。

### 4.2 避让

1. Helper 渲染端 `sprite/avoid.js`：两个开关任一开着才启动；先 `petBridge.setAvoidConfig({enabled, pollMs})`。
2. 主进程 `main.js` 的 `pet:avoid-config` → `main/foreground.js` 起**一个**长驻 PowerShell
   （`GetForegroundWindow` / `GetWindowRect` / `GetWindowThreadProcessId`），按拍打一行 JSON。
3. 每行 + 本窗口所在显示器的 `{bounds, workArea}` 经 `pet:foreground` 推给渲染端。
4. 渲染端用 `S.parseForegroundLine` → `S.avoidWantHide`（自己 pid 不触发、白名单、全屏、最大化）→
   `S.advanceAvoid`（`avoidDelayMs` 才开始躲、`avoidRestoreDelayMs` 才回来）→ 只在翻转时
   `petBridge.setAvoidHidden(bool)` + 打一行日志 + 节流 5s 上报 `POST /screen/event`。
5. 主进程 `pet:avoid-hidden` → `petWindows.setAvoidHidden(win, bool)`。

## 五、实机验证（2026-11-15，本机 3840×2160 @100%）

- 截屏：`识屏已上传 1280×720 scale=1`；`?debug=1` 落盘的 `screen-frame.jpg` 用 `read_image` 看过，
  是真实桌面（编辑器 + 浏览器 + 设置页），不是黑图。
- 识屏：模型回过「你屏幕上开着好几个 DeepSeek 的网页和调试窗口…」「满屏的模型文件和设置面板，
  你这是在熬夜搞配置吧」——人设与读图都对，气泡正常。
- 避让：白名单 `chrome.exe` 时 `避让隐藏 原因=app`；前台切走后 `避让恢复 原因=—`。
- `GET /screen/state` 回十三个归一化后的值 + `last.text` + `foreground`（`app=notepad++ decision=show`）。
- 验证完成后**已把用户配置改回默认关**（识屏每拍一次会花钱）。要再验：
  设置页「系统 → 看屏幕与避让」开开关 → 保存（会重启桌面 Helper）→ 右键「看一眼屏幕」或等一拍。

### 没能验到的

- **4K/150% 缩放下的黑图**：本机是 3840×2160 @100%，`scale=1`。黑图判定与 `getDisplayMedia` 兜底
  都有单测与代码路径，但没在 150% 机器上复现过。要验请在有缩放差异的机器上 `?debug=1` 取一张图看。
- **macOS / Linux 的避让**：只做 Windows（`foreground.js` 在非 win32 直接返回 false，一条进程都不起）。

## 六、踩坑（P4 新增，编号续 P3 的 42）

43. **宿主推不动 Helper，方向只有一个**：Windows 上 Electron 主进程收不到 piped stdin（见 `helper/bridge.ts`），
    所以「什么时候拍/躲」只能是 Helper 主动问宿主。任何「宿主定时命令 Helper」的设计在这套壳里都跑不通。

44. **PowerShell 输出必须显式 UTF-8**：`[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`。
    不设时中文 Windows 打的是 GBK，Node 按 utf8 解码 → 中文窗口标题变乱码 → 白名单里的
    「哔哩哔哩」这类标题永远匹配不上（而且看起来像「规则没生效」）。

45. **PowerShell 的 `$pid` 是自动变量**：`$pid = ...` 会静默变成只读失败。前台采集里用 `$winPid`。

46. **判定放渲染端、采集放主进程**：主进程是纯 JS，拿不到 `src/shared` 的 TypeScript 实现。
    把 `shared/avoid` 照抄一份进 `main/` 就是两套规则；正确切法是主进程只做「采集 + 显示器矩形 + hide/show」，
    解析与判定都过 `S.*`（`shared-core.js` 由 `scripts/build-desktop-core.mjs` 打包）。

47. **避让与托盘的隐藏必须相乘**：`windows.setAvoidHidden` 用独立的窗口 id 集合记账，
    托盘的 `setHidden(false)` 会跳过被避让藏起来的窗口，避让收尾也不会越过 `manualHidden`。
    窗口重建（`closeAll`）时集合必须清空——窗口 id 会变，旧 id 留着等于新窗口永远躲不开。

48. **黑图不上传**：判黑是花钱的门。`desktopCapturer` 的缩略图在某些缩放下尺寸正确、内容全黑，
    发上去只会白花一次读图钱还换来一句瞎话。回退是渲染端的 `getDisplayMedia`（原生分辨率），
    取完立刻 `track.stop()`（系统录制角标跟着消失）。

49. **识屏只出气泡、不念**：念一句会额外计费且与碎碎念抢音频；要念再加开关（目前没有对应配置键）。
