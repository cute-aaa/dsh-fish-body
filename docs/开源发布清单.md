# 开源发布清单（dsh-fish-body）

> 用途：把「这个项目要开源」从一堆散落的判断，收敛成一份可勾选、可复核的执行基准。
> 每一条都附了**判据**（怎么算做完）与**证据位置**（改哪个文件 / 跑哪条命令）。
> 更新方式：做完一条勾一条；决策变了改这里，不要在聊天里改。

## 0. 三条口径（先对齐，其余都从这三条推出来）

1. **代码归代码，素材归素材。** 代码 MIT；素材 CC BY-NC-SA 4.0（非商业 · 署名 · 相同方式共享）；第三方组件各自许可。三者互不覆盖，读者只看 `LICENSE` 时也必须看到这个分层——所以范围声明要写在 `LICENSE` 顶部，不能只藏在 `NOTICE` 里。
2. **仓库默认只发代码 + 最小可运行素材。** 一切体积大、授权存疑、需要另外授权的资源（大动画包、商业字体、Live2D Cubism Core、表情包）都走**运行期获取**：用户主动点、有哈希校验、能离线导入、失败有降级。
3. **运行期获取不是「甩包袱」。** 每一条获取路径都必须回答四个问题：从哪来、多少字节、怎么校验、拿不到时退回什么状态。

## 5. 历史剥离

### 5.1 先备份（不可跳过）

```powershell
git clone --mirror G:\Projnew\ai\dsh-fish-body H:\backup\dsh-fish-body-$(Get-Date -f yyyyMMdd).git
git bundle create H:\backup\dsh-fish-body-$(Get-Date -f yyyyMMdd).bundle --all
git bundle verify H:\backup\dsh-fish-body-*.bundle
```

两份都要：mirror 用于随时回滚，bundle 用于异地冷备。**不在原仓上跑 filter-repo**——原仓是唯一可信源。

### 5.2 分析后再定范围

```powershell
git clone --no-local G:\Projnew\ai\dsh-fish-body H:\oss\dsh-fish-body
cd H:\oss\dsh-fish-body
pip install git-filter-repo
git filter-repo --analyze
Get-Content .git\filter-repo\analysis\path-all-sizes.txt -TotalCount 25
```

| 分析结论               | 剥离范围                                 | 结果体积 | 代价                                                         |
| ---------------------- | ---------------------------------------- | -------- | ------------------------------------------------------------ |
| `preview` ≥ 50 MB      | preview + fonts + cubism + memes + video | ≈80 MB   | 无（这些本就不发布）                                         |
| `artifacts` 也 ≥ 10 MB | 再加 `artifacts`                         | ≈65 MB   | 内部 DevFlow 记录不公开                                      |
| 要求 < 30 MB           | 再加 `assets/webm`                       | ≈25 MB   | **旧 tag 不可再构建**，需在 README 注明「历史 tag 仅作追溯」 |

### 5.3 三个必踩的坑

1. `NOTICE` 里引用的 `be4536d` 会失效 → 改成只引 tag 名。
2. 旧 tag 指向的树若被剥空 → 那些 tag 不能再重跑 `release-app.yml`。
3. filter-repo 会删掉 remote → 必须重新 `git remote add origin`，再 `git gc --aggressive --prune=now`。
