## 九、踩过的坑（别重复）

| 坑 | 结论 |
|---|---|
| pnpm 跨盘 `link:G:/…` | 会拼成坏路径；改用 `D:\NodeJS\DSH\plugins\dsh-fish-body` 联接 + `link:D:/…` |
| `.bat` 用 LF 换行 | cmd 对 LF-only 的 `for/f (...)`、`if (...) else (...)` 块会卡死；**必须 CRLF**，多行块用 `goto` 拆开 |
| `start "" /b` 启 node | node 继承控制台，父 cmd 退出时控制台关闭 → node 收到 CTRL_C 死掉；用 `start "名字" /min <bat>` |
| 计划任务里跑长驻进程 | 用独立控制台；任务本身跑完就结束，别让 node 当任务主进程 |
| 同一 id 在 bundle 与 profile patch 重复 insert | 会出现重复 entry；profile patch 只保留 `disabled: false` 的覆盖行 |
| web profile 的 `pnpm install` | 既有的 `dsh-purge` store 不一致（期望 1.1.90，store 1.1.92），会失败；不是我们造成的，装插件前先修 |
| HMR | 只对 `assets/*.js` 之类静态文件生效；host 代码改动必须重启 |
| 客户端模块 id 写死 | `src/client/index.ts` 的 `id: 'dsh-pet'` 必须与 `package.json` 的 `name`、配置树 entry id 一致；改名后忘了改就会 `client-modules: could not load "dsh-fish-body"`（服务端 bundle 能 200，但浏览器 boot 失败）。改名后**必须 `pnpm build`** |
| `/plugins/??…` 需要 `&rev=` | 模块组合 URL 带 `rev`，模块图或 bundle 变化后旧 rev 会 404；排查时用页面里最新的 rev，别手拼 |
