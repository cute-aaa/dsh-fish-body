## 四、架构定调（灵魂，不可偏离）

1. **人设 = 灵魂**（dsh-soul / fish-soul 只出 name + 正文，fish-body 经 `PersonaSource` 原生导入）。
2. **动画 = 表现形式**（webm / layered png / live2d 三种互斥，作为人设的展示方式）。
3. **fish-body = 展示层**：人设 + 动画汇合。
4. **`Renderer` 只管「视觉 + 动作播放」；交互与运动（拖拽/走位/抛掷/挤压/菜单/状态/点击）留在卡片层**。这条是硬边界。
5. 三种渲染后端互斥，`pets[].renderer` 决定；皮肤/模型选择 `pets[].model` 决定。

## 五、渲染层现状（读代码顺序）

### 5.1 契约 `src/client/pet/render/types.ts`

```ts
interface Renderer {
  readonly kind: RendererKind;            // 'webm' | 'layered' | 'live2d'
  mount(stage, opts): void | Promise<void>; // opts: { size, assetRoot, source }
  destroy(): void;
  playAction(name, opts?: { once?, playbackId? }): void;
  setIdle(name): void;
  setEndedHandler(cb): void;               // webm 播完判定回调
  stopLooping(): void;
  setFrozen(frozen): FreezeCue | null;
  isFrozen(): boolean;
  frontElement(): HTMLElement | null;      // webm 返回 <video>；layered/live2d 返回 null
  progress(): PlaybackProgress;
  setMouth?(open): void;                   // 口型（P3 语音联动用）
  setGaze?(x, y): void;
  setMood?(mood): void;                    // 未实现
  hitTest?(x, y): string | undefined;      // 命中区（layered 已实现；live2d 暂 undefined）
  gestureAt?(x, y): string | undefined;    // 视口坐标 → 皮肤声明的手势（layered）
  listActionGroups?(): RendererActionGroup[]; // 右键「动作」树（layered 手势 / live2d motion、expression）
  readonly ready: boolean;
}
```

`AnimationSource`（卡片注入给渲染器）：`cfg()/currentAnim()/workStatus()/facing()/report()/clearCuePlayback()/
onFrontReady()/isDragging()/initiallyFrozen`。`RendererCfg` 含 `model?: string`（皮肤/模型选择）。

### 5.3 三个渲染器

| 文件 | 说明 |
|---|---|
| `render/webm.ts` | 内部持 `createOwnAnimation`（`src/client/pet/animation/animation.ts`，引擎不动）；`playAction` 识别 http(s) 绝对地址走 url 插播；`progress()` 读 `frontVideo()`。 |
| `render/layered.ts` | 扫描 `pet/<root>-skin/manifest.json` + `art/*.png`，canvas 合成；`computePoses/drawPoses/hitTest` 在 `layered/rig.ts`；manifest 解析在 `layered/types.ts`。 |
| `render/live2d.ts` | `pixi-live2d-display/cubism4` + Cubism Core（动态注入 `<script>`）；`mount` 拉 `/skin/<root>/models` 选 `.model3.json`；口型/视线走 `ParamMouthOpenY/ParamEyeBallX/Y`。 |

**关键语义**：`frontElement()` 只有 webm 返回 `<video>`（卡片层走位/挤压读它）；layered/live2d 返回 `null`，
于是走位/挤压/落地挤压自然跳过——这是有意的，别为了「能挤压」改成返回 canvas。

### 5.4 卡片层 `src/client/pet/card/`

- `entry.ts`：右键菜单；**已含「渲染方式」子菜单 +「模型」子菜单**（modelsRef 在挂载时拉 `/skin/<root>/models`），
  动作树经 `actionMenuTree(renderer, animations, renderer.listActionGroups())` 取（T2.5）。
- `menu-actions.ts`：`switchDisplay/switchRenderer/switchModel` 三个切换动作（POST `/pet-display`、`/pet-renderer`、`/pet-model`）；
  `action: 'renderer-action'` 的叶子直接调 `playRendererAction` → `renderer.playAction(name)`，不进动画链。

## 七、T2.5 收尾（已完成，2026-11-11）：菜单随渲染方式差异化

**落到哪**：判据与菜单数据在 `src/shared/menu/renderer-actions.ts`（纯函数，浏览器与桌面经 shared-core 共用）：

| 导出 | 作用 |
|---|---|
| `skinMenuGroups(menu)` | 皮肤 `interaction.menu` → 动作组。只认 rig 能做的装配手势（pat/poke/tailpet/wag/hop/blink/talk/mouth/jelly…，文案见 `SKIN_GESTURE_LABELS`，`name` 仍是手势 id 以便 `assemblyActionOf` 直认）；`separator` 与宿主应用命令（resize / recenter / hide / quit）跳过，重复项去重。 |
| `model3ActionGroups(raw)` | `FileReferences.Motions` 每组一张子菜单（多条目用 `组名 序号`），`Expressions` 合成「表情」组；动作名编码为 `motion:<组>:<序号>` / `expression:<名>`。未声明时返回 `[]`（DeepSeek 公皮就是这一种）。 |
| `rendererActionTree(groups)` | 动作组 → `动作` 菜单树；只有一组时条目直接摊平，多组时每组一层；空组/空标签剔掉，全空返回 `[]`（不产出空菜单）。 |
| `actionMenuTree(renderer, animations, groups)` | 两端唯一的选树入口：`webm` → `buildMenuTree(animations)`；`layered`/`live2d` → `rendererActionTree(groups)`。 |

- `Renderer` 新增可选 `listActionGroups?()`：layered 在 `mount` 解析清单后填（`skin.interaction.menu`），

  `deps.playRendererAction`（`runtime.ts` → `renderer.playAction(name)`），不进卡片动画链（这类动作没有 webm 段，
  没有「播完」可言）。睡觉闸门沿用「打扰类一律拒」。
- **两端都注入「渲染方式 / 模型」**：`rendererMenuBranch(current, available)` 打勾当前项、把缺素材的后端标

## 九、踩坑（别重复）

1. **`D:\NodeJS\DSH` 是文件不是目录**；一律用 `D:\NodeJs\DSH_home`。
2. **改 host 代码必须重启 fish**；客户端也无热替换，都要 `pnpm build`。
3. **`scripts/prepare.js` 会重写 package.json 的 `files` 数组**（发布清单）。新增包内资产目录必须同时加进 `prepare.js` 的 `keep`
   数组 + `assets/` 目录，否则发布会漏（`assets/cubism` 这次就是这样踩的）。
4. **pnpm 跨盘 link 会拼坏路径**；用 `D:\NodeJs\DSH_home\plugins\dsh-fish-body` junction + `link:../../plugins/...`。
5. **`pets[].model` 是可选字段**：merge/save 只在非空才落键（与 `whisperPrompt` 同口径），**不需要**写进默认 `assets/config.jsonc`；
   `renderer` 是必填默认（webm），已在默认配置里。
6. **Cubism Core 是 wasm 内嵌单文件**（`live2dcubismcore.min.js` 206KB，官方 SDK 5 的 `Core/` 下），无单独 `.wasm`；
   通过 `/cubism/live2dcubismcore.min.js` 路由供给，客户端动态注入 `<script>` 后读 `window.Live2DCubismCore`。
7. **pixi-live2d-display@0.4.0 配 pixi.js@6**（不是 v7/v8）；`cubism4` 入口引用全局 `Live2DCubismCore`。
8. **DeepSeek 公皮 model3.json 没声明 Motions/Expressions**（`Animation/`、`Exp3/` 文件在但没挂），所以 `playAction` 的动作/表情静默降级为自然运动。
9. **layered/live2d 的 `frontElement()` 返回 null**：卡片层 `frontVideo()` 因此为 null，走位/挤压/落地挤压自然跳过——这是有意为之，别为了「能挤压」把它改成返回 canvas。
10. **全量 `npm test` 里 `work-status-lifecycle.test.ts` 有挂起/失败**（与渲染层无关，是既有问题）；跑门禁用 `typecheck/lint/format:check/check:cycles/build`，测试单独跑相关文件即可。
11. **`lib/client.js` 绝不能有顶层 ESM import**：DSH 把它当经典脚本加载，裸 import 会直接
    `SyntaxError: Cannot use import statement outside a module`，整个插件 entry 激活失败。
    pixi / pixi-live2d-display **不进 bundle**（ESM 打进来还会带出 node 的 url/punycode 垫片，
    且 cubism4 求值时就要求 `window.Live2DCubismCore` 已存在）：由 `scripts/prepare.js` 从依赖里拷出
    UMD 到 `assets/vendor/`，`/vendor/<file>` 路由供给，`render/live2d.ts` 按
    Core → pixi → cubism4 的顺序 `<script>` 注入，模型从 `PIXI.live2d.Live2DModel` 取。
    改渲染依赖后务必 `grep '^import ' lib/client.js`（必须为 0）+ 确认 `assets/vendor` 两个文件在。
12. **桌面 Helper 的 CSP 必须放 `'unsafe-eval'`**：pixi 6 编译着色器要 `new Function`，缺它 live2d 直接报
    `Current environment does not allow unsafe-eval`（浏览器端能跑是因为 DSH 页面本来就允许）。
    `script-src` 同时要放 `http://127.0.0.1:*`（`/vendor`、`/cubism` 的脚本来源）。
13. **helper 的日志通道分两级**：helper 主进程 `console.log` 走 stdout → 宿主按 **debug** 级落盘（默认看不到），
    `console.warn/error` 走 stderr → 宿主按 **warn** 落盘。排查渲染问题一律用 warn，否则「什么都没打」是被过滤了。
    `DSH_PET_DEBUG=1` 起宿主时，窗口加载 12s 后会往日志打一行 `[dsh-pet-debug]`（sprites/visual/canvas/pixi 探针）。
14. **视频元素必须留在 stage 里**：`sprite/init.js` 的 webm 分支曾经漏掉 `stage.appendChild(videoA/B)`，
    表现是「窗口在、精灵在、画面全透明」——sprites=1 但 visual=0；改 buildDom 时别只建元素不挂载。
15. **`main` 宠物没有 `main-skin`，也没有 `.model3.json`**：把它的 `renderer` 切成 layered / live2d 会挂载失败
    （`皮肤目录没有 .model3.json：main` / `皮肤 manifest HTTP 404`），窗口还在、画面空白。菜单现在按探测结果
    把这两项置灰，别再靠手改配置绕过；真要给鱼生加分层/live2d，得先按 `docs/参考项目-皮肤导入.md` 做出
    `pet/main-skin/`（清单 + 分层图）或放 `.model3.json`。
16. **自动化浏览器要带 token**：裸开 `http://127.0.0.1:3099/` 会被访问闸门挡在 401（页面里连宠物 DOM 都没有）；
    宿主启动时日志会打 `dsh web: http://127.0.0.1:3099/?token=…`（见 `DSH_HOME/logs.txt`），用这个 URL
    起 Playwright（`channel: 'msedge'`, headless）就能真实右键、截图。菜单根节点 `.dsh-pet-menu` 自身没有尺寸，
    `waitForSelector` 要用 `state: 'attached'`，尺寸与可见性看 `.dsh-pet-menu-column`。

## 十二、决策记录：桌面壳暂不更换（2026-11-11）

**决策**：保留 Electron Helper，不迁移到 WebView2 / Tauri / C# 壳。

**依据（实测数字）**：Electron 运行时 347 MB 磁盘、单宠物 4 进程（WS ≈428 MB / Private ≈241 MB）；
换 WebView2 只省磁盘与首启下载，**不省内存**（同为 Chromium）；而要付的代价是「三平台二进制矩阵 +
签名/公证 + Rust 或 C# 工具链 + 系统 webview 三套行为对齐」。渲染层已与壳解耦（见第十三节），
换壳不会让渲染变简单，所以没有「先换壳再写渲染」的顺序优势。

**恢复评估的触发条件**（任一条成立再开新会话做 B）：
1. 首启下载 347 MB 成为实际投诉/分发阻碍；
2. 桌面端需要 Windows 之外的平台，或反过来明确砍掉 macOS/Linux；
3. helper 的内存/崩溃率在长跑里成为主要问题。

**B 会话的启动姿势**：新开会话，读本文件 + 本决策；先写 `docs/ADR-desktop-shell.md`（平台取舍、
桥协议 `window.petBridge` 对齐清单、透明/穿透/置顶/托盘/DPI/运行时兜底验收表），再动手搭壳。
可原样搬运的是 `index.html` + `sprite/*` + `shared-core.js` + `layered-core.js`（纯 web 渲染层），
要重写的是 `main/*` + 看门狗 + DPI + 平台 shim（约 1900 行）。
