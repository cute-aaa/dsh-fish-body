## 四、架构定调（灵魂，不可偏离）

1. **人设 = 灵魂**（dsh-soul / fish-soul 只出 name + 正文，fish-body 经 `PersonaSource` 原生导入）。
2. **动画 = 表现形式**（webm / layered png / live2d 三种互斥，作为人设的展示方式）。
3. **fish-body = 展示层**：人设 + 动画汇合。
4. **`Renderer` 只管「视觉 + 动作播放」；交互与运动（拖拽/走位/抛掷/挤压/菜单/状态/点击）留在卡片层**。这条是硬边界。
5. 三种渲染后端互斥，`pets[].renderer` 决定；皮肤/模型选择 `pets[].model` 决定。

## 五、渲染层现状（读代码顺序）

### 5.1 契约 `src/client/pet/render/types.ts`

```ts
interface Renderer {
  readonly kind: RendererKind; // 'webm' | 'layered' | 'live2d'
  mount(stage, opts): void | Promise<void>; // opts: { size, assetRoot, source }
  destroy(): void;
  playAction(name, opts?: { once?; playbackId? }): void;
  setIdle(name): void;
  setEndedHandler(cb): void; // webm 播完判定回调
  stopLooping(): void;
  setFrozen(frozen): FreezeCue | null;
  isFrozen(): boolean;
  frontElement(): HTMLElement | null; // webm 返回 <video>；layered/live2d 返回 null
  progress(): PlaybackProgress;
  setMouth?(open): void; // 口型（P3 语音联动用）
  setGaze?(x, y): void;
  setMood?(mood): void; // 未实现
  hitTest?(x, y): string | undefined; // 命中区（layered 已实现；live2d 暂 undefined）
  gestureAt?(x, y): string | undefined; // 视口坐标 → 皮肤声明的手势（layered）
  listActionGroups?(): RendererActionGroup[]; // 右键「动作」树（layered 手势 / live2d motion、expression）
  readonly ready: boolean;
}
```

### 6.1 live2d 模型格式约定（给"用户自己放模型进来"的答案）

**首选：VTube Studio 工程目录原样丢进来**。把整个模型文件夹放进 `pet/<素材根>-skin/models/`（可以多层）即可，
本插件按 VTube 的口径读它：

- `model3.json` 通常**不写** `Motions` / `Expressions`；真正的入口是同名的 `<模型名>.vtube.json` 里的
  `Hotkeys`。宿主在下发清单前把这些补进 `FileReferences`（见 `src/host/vtube.ts` + `src/host/model-extras.ts`）：
  - `Action: TriggerAnimation` + `File: X.motion3.json` → 动作条目，**菜单文案用热键名**（「抚胸手打开」
    而不是「默认手切举手」），`FadeSecondsAmount` → `FadeInTime`，`StopsOnLastFrame` 原样带出；
  - `Action: ToggleExpression` + `File: X.exp3.json` → 外观条目（名字取热键名）；
  - `RemoveAllExpressions` / 移动模型 / 道具这类热键不是素材，跳过；

| ---------------- | --------------- | ---------------- | ------------------------------------------------- |

### 7.1 插件重启（免重启整个 profile，2026-11-11）

**为什么能做**：fish profile 由 `dsh web --profile fish` 拉起，`profileContext` 存在 → base 组合包里的 `hmr`
条目是**启用**状态（`root: []`，只监听 profile 配置，不扫源码目录）。HMR 的 profile 重新组合会替换
「已加载文件变过」的插件——包括 `link:` 进来的包（本插件就是 link 到工作区的），所以 `pnpm build` 之后
只要触发一次重新组合，新 `lib/index.js` 就生效，不用杀 3099 进程。

**端点**：`POST /plugin-restart`

- 有 HMR：**先回** `{ ok: true, mode: 'hmr' }`，`150ms` 后在 `hmr.runExclusive(() => hmr.reconcileProfile())`
  里重新组合（`reconcileProfile` **必须**在 `runExclusive` 的事务里调，否则 AsyncLocalStorage 判定失败直接抛
  `HMR profile reconciliation must run inside runExclusive`）。不先回响应的话，重新组合会把本插件的路由一起拆掉，
  应答写不出去。
- 无 HMR：进程内换不掉已加载的 ESM，只 `requestRestart()`（重建桌面 Helper），响应回 `mode:'helper'`，客户端提示
  「宿主代码改动仍需重启 profile」。

**入口**：网页右键「重启插件」（`menu-actions.ts`，`mode=hmr` 时 1.2s 后自动 `location.reload()` 拿新 client.js）、
桌面右键「重启插件」（`sprite/menu.js`，Helper 由宿主重建）；两端都是维护类，睡着时放行。

**验证（2026-11-11 实测）**：

1. `POST /plugin-restart` → `{"ok":true,"mode":"hmr"}`，`logs.txt` 出现 `插件重启请求 mode=hmr` 与
   `插件重启完成 swapped=0`（没有文件变化时是 no-op，符合预期）。
2. 代码是否真换掉：临时把日志文案改成 `插件重启请求(v2) mode=` → `pnpm build` → 第一次 POST（旧代码执行）后
   `logs.txt` 出现新的 `桌面判定…`（插件已重应用）；**第二次 POST 打出 `插件重启请求(v2)`** → 新模块确实在跑。
3. 随后还原文案、重建、再 POST 两次，日志回到不带 `(v2)` 的文案 → 最终产物干净。
4. 同时验证 `main` 用上 DeepSeek 公皮：切 `renderer=live2d` 后 Helper 日志
   `桌面 live2d 已挂载 pet=main 模型=大肥鱼.model3.json`，无挂载失败。

### 7.2 live2d「黑鼻子」修复（2026-11-11）

**现象**：DeepSeek 公皮鼻梁上一块黑方块（浏览器与桌面都复现，与卡片层无关）。

**定位过程**：把模型单独挂到一个空白 PIXI 应用里同样复现 → 逐部件隐藏：隐藏 `鼻子` 部件（cdi3 名称）

其余透传。网页 `render/live2d.ts` 与桌面 `sprite/backend.js` 读同一张表。

### 7.5 动作与外观的叠加层（2026-11-12）

**为什么必须自己管队列**：`pixi-live2d-display@0.4.0` 的 cubism4 后端把所有 motion 塞进同一个
`MotionQueueManager`，而 `Cubism4MotionManager._startMotion` 一进来就 `stopAllMotions()`——用
`model.motion()` 点第二个动作，第一个**连同待机**一起被掐掉；expression 更是单槽（`expressionManager`）。
VTube 的用法正相反：热键动作叠在待机之上，外观是多选开关。

**做法**（两端同构：`src/client/pet/render/live2d/overlay.ts` / `runtime/electron-helper/sprite/overlay.js`）：

- 每条叠加物一个独立的 `CubismMotionQueueManager`（库已从 UMD 导出，连同 `CubismMotion` /
  `CubismExpressionMotion`）；`CubismMotion.create(json)` 后 `setIsLoop(false)`——文件里的 Loop 是给待机循环用的，
  热键动作一律播一遍，否则手臂会来回抖。
- 挂在 `internalModel.on('beforeModelUpdate')` 推进：那一步在 `model.update()` 之前、`loadParameters()` 之前，
  写入只影响本帧，不会把姿态污染成下一帧的基准。
- **定格**（`StopsOnLastFrame`）：播完后按 `shared/live2d-motion3.ts` 的 `parseMotion3().finals` 每帧写回末帧参数
  （参数走 `setParameterValueById`，部件显隐走 `setPartOpacityById`）。先写定格、再推进活动层，新动作才能盖住旧定格。
- **上限 8 条**（超出淘汰同类最早的一条），`destroy` 时摘钩子并清空。
- 菜单语义：动作 = 叠加触发 + 末尾「恢复默认动作」（`MOTION_RESET`）；外观 = `toggle` 开关 + 「恢复默认外观」（`EXPRESSION_RESET`）。

**为什么不用 `afterMotionUpdate`**：那之后紧跟 `model.saveParameters()`，我们写的值会被存成「已保存状态」，
`loadParameters()` 再也还原不回去——叠上去的姿态会变成永久粘住。

### 7.8 云端 TTS 骨架 + 密钥走 DSH 凭据库（T3.5 / T3.6 收尾，2026-11-15）

这一轮解决的是「接入第三个嗓子之前必须先有的两件事」：云端实现的配置位，以及密钥该存在哪。

**① 云端骨架（`src/host/voice/cloud/provider.ts`，`id: cloud`）**

- `CLOUD_FIELDS` 四项：`baseURL`(必填) / `model`(必填) / `voice`(可选) / `apiKey`(`password` + `credentialRef`)。
- `availability()` **恒为假**，理由分两种：缺项 → `未配置云端语音：还缺 服务地址 / 模型`；
  配齐 → `云端 TTS 尚未接入（骨架）：配置已保存，合成会落到本地语音或 edge`。
  **为什么恒假**：一旦放行，回退链会把它排在本地语音之前，每句话先失败一次再落到下一环——
  多一次 400、多一行 `link cloud failed`，用户只觉得变慢了。
- `synthesize()` 直接抛「云端 TTS 尚未接入（T3.5 骨架）」：骨架不假装成功。
- 注册在 `host/index.ts` 的 GSV 之后：日后真正放行时本地优先（延迟与费用都更低）。

**② 密钥字段走凭据库（`src/host/voice/provider-secrets.ts` + `src/host/routes/voice-provider-config.ts`）**

`VoiceField` 多了可选 `credentialRef`：`kind: 'password'` **且**声明了引用名的字段才算密钥，值写进
DSH 凭据库（`ctx.credentials` 的 `describe/set/unset`），`voice-providers.json` 里一个字节都不留。

| 语义       | 做法                                                       | 为什么                                                                    |
| ---------- | ---------------------------------------------------------- | ------------------------------------------------------------------------- |
| 读         | `GET` 回 `values`（不含密钥）+ `secrets: { apiKey: true }` | 值从不回传：配置文件会被备份、会被贴进 issue                              |
| 写         | `patch.apiKey` 非空才写                                    | 界面只能给空框（没值可显示）；空串若当「删」，每次保存都会清掉密钥        |
| 删         | 显式 `clear: ['apiKey']`                                   | 「留空 = 不改 / 清除 = 单独按钮」这两件事必须在协议层分开                 |
| 宿主不能写 | `unsupported`                                              | 独立模式的 `credentials` 替身只有 `resolve`；静默丢弃会让用户以为保存成功 |

**结构探测而不是直接调**：`providerSecretSeamOf(raw)` 检查三个方法都在才返回适配器，否则 `null`。
独立模式（`lib/standalone.js`）的替身形状由此自然降级，不需要第二套分支。

**③ 设置页：每个实现一张接入卡**

- 新增 `client/settings/use-provider-forms.ts`：按 `providerId` 分桶管草稿、密钥在场、保存结论与启停状态

  （`hasProcessScript()`），云端卡因此没有「启动服务」。
- 分区里多一层 `section(t('voiceProviderTitle'))` 把接入卡聚在一起；`voiceProviderHint` 改成通用文案，
  新增 `voiceProviderSecretSaved` / `voiceProviderSecretClear` 两条键（8 种语言全补）。

**④ 契约与验证**

## 九、踩坑（别重复）

1. **`D:\NodeJS\DSH` 是文件不是目录**；一律用 `D:\NodeJs\DSH_home`。
2. **改 host 代码必须重启 fish**；客户端也无热替换，都要 `pnpm build`。
3. **`scripts/prepare.js` 会重写 package.json 的 `files` 数组**（发布清单）。新增包内资产目录必须同时加进 `prepare.js` 的 `keep`
   数组 + `assets/` 目录，否则发布会漏（`assets/cubism` 这次就是这样踩的）。
4. **pnpm 跨盘 link 会拼坏路径**；用 `D:\NodeJs\DSH_home\plugins\dsh-fish-body` junction + `link:../../plugins/...`。
5. **`pets[].model` 是可选字段**：merge/save 只在非空才落键（与 `whisperPrompt` 同口径），**不需要**写进默认 `assets/config.jsonc`；
   `renderer` 是必填默认（webm），已在默认配置里。
6. **Cubism Core 是 wasm 内嵌单文件**（`live2dcubismcore.min.js` 206KB，官方 SDK 5 的 `Core/` 下），无单独 `.wasm`；
   通过 `/cubism/live2dcubismcore.min.js` 路由供给，客户端动态注入 `<script>` 后读 `window.Live2DCubismCore`。
7. **pixi-live2d-display@0.4.0 配 pixi.js@6**（不是 v7/v8）；`cubism4` 入口引用全局 `Live2DCubismCore`。
8. **DeepSeek 公皮 model3.json 没声明 Motions/Expressions**（`Animation/`、`Exp3/` 文件在但没挂），所以 `playAction` 的动作/表情静默降级为自然运动。
9. **layered/live2d 的 `frontElement()` 返回 null**：卡片层 `frontVideo()` 因此为 null，走位/挤压/落地挤压自然跳过——这是有意为之，别为了「能挤压」把它改成返回 canvas。
10. **全量 `npm test` 里 `work-status-lifecycle.test.ts` 有挂起/失败**（与渲染层无关，是既有问题）；跑门禁用 `typecheck/lint/format:check/check:cycles/build`，测试单独跑相关文件即可。
11. **`lib/client.js` 绝不能有顶层 ESM import**：DSH 把它当经典脚本加载，裸 import 会直接
    `SyntaxError: Cannot use import statement outside a module`，整个插件 entry 激活失败。
    pixi / pixi-live2d-display **不进 bundle**（ESM 打进来还会带出 node 的 url/punycode 垫片，
    且 cubism4 求值时就要求 `window.Live2DCubismCore` 已存在）：由 `scripts/prepare.js` 从依赖里拷出
    UMD 到 `assets/vendor/`，`/vendor/<file>` 路由供给，`render/live2d.ts` 按
    Core → pixi → cubism4 的顺序 `<script>` 注入，模型从 `PIXI.live2d.Live2DModel` 取。
    改渲染依赖后务必 `grep '^import ' lib/client.js`（必须为 0）+ 确认 `assets/vendor` 两个文件在。

    `Current environment does not allow unsafe-eval`（浏览器端能跑是因为 DSH 页面本来就允许）。

13. **helper 的日志通道分两级**：helper 主进程 `console.log` 走 stdout → 宿主按 **debug** 级落盘（默认看不到），

    分层清单在子目录里靠 `shared/layered-paths.ts` 的候选表找到；新增皮肤布局要么按根 `manifest.json`，
    要么放 `layered/manifest.json`，别自己再发明第三种路径。删 junction 前先确认目标目录还在——

16. **自动化浏览器要带 token**：裸开 `http://127.0.0.1:3099/` 会被访问闸门挡在 401（页面里连宠物 DOM 都没有）；

    `waitForSelector` 要用 `state: 'attached'`，尺寸与可见性看 `.dsh-pet-menu-column`。
17. **改完宿主代码先 `pnpm build`，再右键「重启插件」**：fish profile 的 HMR 是启用的，重新组合会换掉
    link 进来的包；但**必须**在 `hmr.runExclusive(...)` 里调 `reconcileProfile()`，直接调会抛
    `must run inside runExclusive`。响应必须早于触发（组合会拆掉本插件路由）。没有 HMR 的部署（headless/SDK 组合包）

    `Motions`/`Expressions` 就整段让位。别把补全结果写回磁盘（下一次打开 VTube Studio 会当脏数据）。

    canvas 后端补在上边距里单独算，别混。
23. **edge TTS 偶发「第一次调用失败」**：`@andresaya/edge-tts` 每次合成都要先拿一次 DRM 令牌，冷启动或间隔久了之后第一句可能抛错
    （表现是 `generate-error`，紧接着再发一句就正常；同一句在 Node 里直接调 `synthesize()` 又能过）。这是上游偶发，不是本地代码：
    **T3.3 已在链上给内置实现加了「失败重试一次」**（`voice/chain.ts` 的 `builtinLink`），别在路由层再叠重试。
24. **`/voice/speak` 的 Content-Type 现在跟着合成产出的 mime 走**：别再假设 mp3；缓存目录里可能同时有 `.mp3` 与 `.wav`，
    `findCachedClip` 按已知扩展名逐个探（`voice/audio.ts` 的表是唯一真源），加新格式只改那张表。
25. **目录扫描要认目录链接**：`readdirSync(dir, { withFileTypes: true })` 里 junction / symlink 的
    `entry.isDirectory()` 是 **false**，只按它筛会漏掉所有软链过来的皮肤目录（`main-skin/layered-03` 就是这么消失的）。
    判目录用 `entry.isDirectory() || entry.isSymbolicLink()`，再用 `existsSync(join(dir, name, 'manifest.json'))` 复核。
26. **「外观」曾经只能是单选**：Cubism 运行库的 `expressionManager` 是单槽（`model.expression(name)` 换的是当前那一个）。
    2026-11-12 已改成叠挂（§7.5）：插件自己管队列、在 `beforeModelUpdate` 逐帧写参数，外观因此是多选开关。
    改回去（用 `model.expression()`）就会退回一档一档切。
27. **`model.motion()` 一进来就清空队列**：`Cubism4MotionManager._startMotion` 内部先 `stopAllMotions()`，
    所以「点第二个动作」= 第一个连同待机一起没了。要叠就只能像 §7.5 那样每条一对独立队列。
    另外它不认文件里的 `Loop`，请自己 `setIsLoop(false)`，否则动作会反复来回抖。
28. **VTube 热键里的文件名不带目录**：`File` 只有 `X.motion3.json`，实际散在 `Animation/`、`Exp3/` 或模型根目录。
    必须逐个候选目录探（`src/host/vtube.ts` 的 `locate`），探不到的整条丢弃——否则菜单会多出点不动的条目。
29. **画布后端的命中框与 webm 不是同一套**：webm 只占画面中间 37.5% 宽，方形画布几乎铺满整块、头顶还在舞台顶以上。
    命中框比例只在 `shared/body-box` 里维护（网页命中层、拖拽夹取、碰撞框、桌面 `hitRect` 与穿透判定都读它），
    任何一处写死 `HIT_BOX` 都会复发「看得见、点不到头」。桌面主进程没有渲染器知识，所以命中框由渲染端随
    `setBounds` 上报（`margins.hit`），老渲染端不发时才退回旧推导。
30. **GSV 的 `/set_*_weights` 只认正斜杠**：`weights_path=D:\AI\...\x.ckpt` 会让 api_v2 在 `open()` 上抛
    `[Errno 22] Invalid argument`，同一路径写成 `D:/AI/.../x.ckpt` 就 200。`gsv/settings.ts` 的 `toPosixPath`
    是唯一转换点，加新调用别绕过它。
31. **`availability()` 必须同步**（`voice/registry.ts` 的硬约束，链每次合成都现查）：GSV 的探活不能在里面 fetch，
    只能读缓存结论——「注册时探一次 + 每 20s 重探 + 合成失败即标不可用」。
32. **缓存键必须含「嗓子」**：`speak.ts` 原先按「来源 id + 请求里的音色」算键，第三方换音色会命中旧音频，
    听感上是「切了没生效」。现在 `VoiceProvider.cacheTag()` 进键（GSV 回 `音色|gpt|sovits`）。
    加新 provider 时若不实现 `cacheTag`，就别在它内部做多音色。
33. **provider 配置别写进 `main-config.jsonc`**：那份带大量手写注释，整份重写会把注释与排版抹平；
    `voice-providers.json` 单独一份普通 JSON 才能安全地读-改-写（`voice/gsv/store.ts`）。
34. **音色包的 ref 可能是相对「音色根上一级」**：`voice-local/voices/loli12-gsv/voice.json` 写的是
    `voicepack/age12/01.wav`（相对 `voice-local/`）。扫描要按「音色目录 → 音色根上一级 → 音色根」三级探，
    只按音色目录会漏掉这一条。
35. **GSV 冷启动与首次合成慢**：进程起来约 40s（模型加载），第一次 `/tts` 峰值 5.5s，稳定后 1.5–3s；
    链上给 GSV 单句 60s 上限，够用且不挡住 edge 兜底。

    （`card/entry.ts` 与 `sprite/menu.js`）。2026-11-12 加「音色」时网页端已经生效，但本机只有 `main`

    排查顺序：`/config` 看 display → 确认右键的是哪一端 → 再看该端菜单构建函数。
37. **托盘在主进程，拿不到渲染端状态**：会话位置、`customPos`、拖拽/飞行都在渲染端，所以「回到初始位置」
    只能发 IPC 命令让渲染端 `goHome()`，别在主进程里算坐标；「隐藏」用 `hide()/showInactive()`，
    别改 `display`——那会触发宿主重启并把窗口关掉，托盘就再也点不回「显示」。
38. **托盘「退出」有两种语义**：独立模式退出整个应用（`shutdownApp` → `/quit`）；DSH 宿主里退出
    **只停桌面助手**（`/desktop/stop`），DSH 继续跑。别在 BRIDGE 下直接 `app.quit()`——宿主会按崩溃
    指数退避重启，表现是「点了闪一下、进程还在」。
39. **「GSV 语音失效」可能不是语音的问题，是控制台被关掉了**（2026-11-14 实测）：`api_v2` 的 `/tts`
    在 `tts_pipeline.run` 之前有一句 `print()`（`api_v2.py:531`）。用 `cmd /c start` 起服务时，
    窗口一被关掉，python 仍然活着（父 `cmd.exe` 已消失、`MainWindowHandle=0`），但 stdout 是废句柄，
    于是 `print` 抛 `OSError: [Errno 22] Invalid argument` → 每句合成 400 → 回退链**静默**换成 edge 的嗓子。
    判据：`/docs` 与 `/set_*_weights` 都 200（这两条路径不 `print`），只有 `/tts` 在 2–5ms 内 400；
    `/voice/speak` 回 `audio/mpeg` 而不是 `audio/wav` 就是它已经在用 edge。
    处理：`startService` 改成不经 `cmd /c start`、把脚本 stdout/stderr 追加到
    `<userRoot>/logs/gsv/<provider>-start.log`（没有窗口可关），并新增 `providers[].lastError`
    让设置页把「通着却念不出来」显示出来。手工起的 `gsv.bat` 也把 python 那行改成
    `>> logs\gsv\api-v2.log 2>&1` 并加 `PYTHONUNBUFFERED=1`。实测两条路径：
    有控制台（双击）时 `api-v2.log` 收全量输出（一次 `/tts` 从 4.9K 涨到 10.3K）；
    无控制台（插件启动）时下游的 venv 启动器会自己开一个隐藏控制台，日志里只有 bat 自己那几行
    ——两种情况下 `print` 都是写进有效句柄，事故那种「stdout 已死」的状态不再出现。
40. **密钥字段的「空串」不是「删掉」**：`voice-providers.json` 里空串确实等于删键（回落代码默认），但
    密钥字段的值**从不回传**给浏览器，界面只能给空框——如果空串也当删，用户每次点保存都会把自己的
    API Key 清掉。所以两条语义在协议层分开：`patch` 非空才写、要删必须显式 `clear: ['apiKey']`。
    加新 provider 的密钥字段时照这条来，别把两者合并成「一个空串表示一切」。
41. **骨架实现别放行 `availability()`**：云端 TTS 现在恒报「尚未接入」不是占位偷懒。链上排在它后面的
    是本地 GSV 与 edge，放行等于每句话先向云端发一次请求、失败一次再落到下一环——用户听到的只是变慢，
    日志里多一堆 `link cloud failed`。等 `synthesize()` 真写好了再放开，那时把理由那句一起删掉。
42. **「改了却没生效」先看插件挂载指向哪**（2026-11-15 实测）：`<DSH_HOME>/plugins/dsh-fish-body` 是个
    junction，本机曾指向 `.agents/worktrees/…`（另一个 checkout），于是主工作区的改动、连 `pnpm build`
    的产物都进不了运行中的 profile——表现是设置页里根本没有新加的「云端语音」卡，而代码、单测、构建全绿。
    判据两条：`(Get-Item $DSH_HOME\plugins\dsh-fish-body).Target` 是否就是本工作区的 `dsh-pet`；
    `GET /dsh-pet-7340/voice/voices` 的 `providers` 里有没有新注册的实现（旧产物里只有 gsv/edge）。

## 十二、决策记录：桌面壳暂不更换（2026-11-11）

1. 首启下载 347 MB 成为实际投诉/分发阻碍；

3. helper 的内存/崩溃率在长跑里成为主要问题。

桥协议 `window.petBridge` 对齐清单、透明/穿透/置顶/托盘/DPI/运行时兜底验收表），再动手搭壳。

## 十四、原生 GSV 接入（2026-11-15，权重配对 + 目录扫描）

**为什么不再用 `.list` 关联**：`.list` 的 `spk_name`、训练实验名、权重文件名三者只是「通常一样」，
任何自动配对都是猜；而权重文件名才是唯一稳定的 id。所以接入入口改成**选一个权重文件**，
在「同目录 → 兄弟权重目录」里找另一侧；参考音频/文本手动选。`.list` 只剩一个辅助功能：
「从文本文件选一行」取第 4 列当参考文本（`POST /voice/text-lines`），不承担关联职责。
读训练日志（`5-wav32k` / `2-name2text.txt`）批量导入**明确不做**：日志会被同名实验覆盖、
格式跨 v1–v5 变过、批量错配代价大；批量的正确形态是每音色一个目录 + 目录扫描。

**权重配对规则**（`src/host/voice/gsv/voice-pack.ts` 的 `findCounterpart`）：

1. `.ckpt` 认作 GPT、`.pth` 认作 SoVITS；归一 id 复用扫描器的 `voiceIdOfStem`（剥 `-gsv`、epoch、版本标记），
   用户输入还会先剥 `vocal_`/`voice_`/`speaker_` 前缀。
2. 搜索范围：同目录 → 配置里的另一侧权重根 → 从当前目录往上 1–2 层里名字像 `*_weights*` 的兄弟目录。
   若权重已在 `<voicesDir>/<id>/` 内，只在本目录找，不外扩。
3. 排序：同版本优先（目录名或文件名的 `v2`/`v5turbo`）→ epoch/step 高 → 同目录 → 路径。
4. 顶端并列（同版本同 epoch 多份）→ `ambiguous`，**不替用户选**，表单里必须挑一份。
5. 找不到 → `missing`（仍可只存参考，音色置灰「缺少 X 权重」）；关掉自动识别且没手选 → `unpaired`。
6. 两侧都已知且版本不同 → 警告「加载可能失败」，不阻塞。

**落盘**（`POST /voice/voice-pack`，`mode: apply`）：

```
<voicesDir>/<id>/
├─ ref.<ext>        ← 复制的参考音频（≤20 MB）
├─ ref.txt          ← 参考文本（空 = 零样本，不写文件）
└─ voice.json       ← engine/ref/ref_text/prompt_lang [+ gpt/sovits 绝对路径指针] + source 溯源
```

- 权重怎么进目录由 `placement` 决定：`pointer`（默认，只写 `voice.json` 绝对路径指针）、
  `hardlink`（同盘 `fs.link` 成真文件，不占双份；跨盘失败**自动退回指针**并写进 `notes`）、
  `copy`（`copyFile`，目录自足，每套约 230 MB）。真文件进目录后**不再写指针**（扫描器直接命中）。
- 权重默认**不复制、不硬链接**（一套约 230 MB），只写指针；权重本来就在该目录时不写指针。
- 参考已存在且没勾「覆盖」时**只补权重**（硬链接/复制是增量动作），不碰参考——用户常常只是把
  「指针音色」改成「目录自足」；真的无事可做才返回 `skipped`（`preview.pending === false`）。
- 覆盖前把已有的 `ref.*`（含别的扩展名）、文本与同名权重改名 `.bak-<时间戳>`，不删除。
- `target: refs` 时写 `<refsDir>/<id>.<ext>` + `<id>.txt`，没有 `voice.json`，**只能写指针**
  （平铺目录里没有「这个音色的文件夹」可放权重，硬链接/复制直接 400）。
- 写盘后立刻 `gsv.rescan()`（清扫描缓存），音色格与右键菜单马上刷新；响应同时带回新的 `scan`。

**目录扫描**（`voices.ts` 的 `scanVoiceFolders`）：`<voicesDir>/<id>/` 里 `voice.json` 变成**可选**，
权重按扩展名认、参考取 `ref.*` 或目录里唯一音频、文本取 `ref.txt`/`<id>.txt`/`<id>.wav.txt`；
权重与全局 `GPT_weights*`/`SoVITS_weights*` 进**同一个索引**（最高 epoch 优先，同分时目录内优先，
`WeightFile.preferred`），版本未知按兼容处理、不误报不一致；`voice.json` 的 `gpt`/`sovits`/`ref`
指针优先于索引（跨盘、不搬文件）。目录里的权重文件名归一 id 与目录名不一致时记诊断，不静默配对。

**设置页**：GSV 接入卡下面一张「音色素材（权重配对）」卡，**默认收起成一行**：卡头右侧是
「导入音色…」与「重新扫描」，正文只报现状——音色目录路径（没配就明说「清单只能列出权重/参考目录里认出来的」）、
`已接入 N / 共 M`、以及「待接入（k）」清单（每条显示 id 与认到的 `权重/参考` 文件名，点「接入…」把
权重、另一侧、参考音频、参考文本、id 一起预填进弹窗）。

「导入音色…」弹窗（`voice-pack-dialog` 样式，`width:min(680px, 100vw-40px)`）：
权重/另一侧/参考音频/参考文本（可「从文本文件选一行」）/音色 id/写入位置/**权重怎么放**
（只写指针 / 硬链接 / 复制）+ 自动识别、覆盖两个勾 + 「预检」「导入」「关闭」。
预检显示配对状态、候选权重、版本、目标路径、**每份权重的去向**（`GPT：复制 · klee-gsv-e10.ckpt`）与警告；
`ambiguous` 时给下拉，未选不允许导入；`pending === false`（没有要写的东西）时导入按钮直接禁用，
不会再点出一个「目标已存在」的空跑。音色 id 默认由权重名推出、可改；目标已存在时默认跳过，勾「覆盖」才写并备份。

**本机实测（2026-11-15，含 `hardlink` / `copy` 两种新放法）**：

- 真实配置扫描不回归：11 条、9 条可合成，`loli12-gsv`（缺权重）与 `norma`（缺参考）仍置灰；
  诊断首行 `权重文件 57 个、refsDir 条目 10 个、音色目录 0 个`；`scan` 模式下这 11 条全算「待接入」
  （`voicesDir` 为空），每条的 `gptWeights` 都能回指到真实文件。
- 选 `GPT_weights_v2/klee-gsv-e10.ckpt` → 自动在兄弟目录找到 `SoVITS_weights_v2/klee-gsv_e8_s288.pth`，
  预览 `matched`、v2/v2、无警告；`apply` 到临时音色目录后 `voice.json` 里是两条绝对路径指针。
- 临时 `voicesDir` 扫描：`klee` 来源变成 `folder`，不再重复；其余 9 条仍来自 `refsDir`。
- 用这个 provider 合成「火元素的用法，我可是很清楚的。」→ 294 444 字节 `audio/wav`（RIFF/WAVE），
  日志两句切权重、`lastError` 为空；测完把 9880 切回 `norma` v5turbo（两次 `set_*` 均 200）。
- `placement: hardlink`，临时目录放在**同一分区**（`D:\AI\AI-Voice\.dsh-accept-*`）：
  `placed = klee-gsv-e10.ckpt, klee-gsv_e8_s288.pth`，硬链接大小 155 312 957 / 85 007 943 字节与原文件一致
  （没有复制），`voice.json` 只有 `engine/ref/ref_text/prompt_lang/source`（不写指针），
  扫描得到 `klee` 来源 `folder`、可合成；删掉临时目录后原权重 size/mtime 不变。
- 同一步骤把临时目录放到 **C 盘**（`%TEMP%`）→ 两次 `fs.link` 都 `EXDEV`，落地**没有失败**：
  `notes` 里两条「硬链接失败（EXDEV…），已退回指针」，`voice.json` 改写成两条指针，仍 `status: written`。
  这就是「硬链接失败不许把整个导入弄崩」的现场证据。
- 目录里已有真文件时 `hardlink` 与全局权重**指向同一个 inode**，扫描挑哪条都一样；
  `copy` 时目录那份会被全局那份压住（版本确定优先），功能无差，但要知道「目录自足」只在换机器/删全局后才显形。

**踩坑**：

1. 覆盖只认新扩展名是不够的：目录里可能已有 `ref.mp3`，导入 `ref.wav` 会变成两套参考；
   预览把「任何 `ref.*` / `<id>.*` 音频」都算「已存在」，覆盖时一并备份。
2. 目录里的权重没有版本标记（直接放在 `<id>/` 下）时版本是未知：配对按兼容处理，
   不要拿它和「已知版本」硬比，否则会误报「版本不一致」。
3. 同 epoch 时目录内文件优先，但**同版本优先于目录优先**：全局 v2 与目录里的未知版本同为 e10 时，
   选全局那一对（版本确定）更安全；目录文件想赢就放进 `v2/` 子目录或文件名带版本。
4. 目录权重与全局权重进同一索引，必须按文件路径去重 + 认领（`claimed`），否则 `klee` 与 `klee-gsv`
   会各建一条音色。
5. `voice.json` 指针是绝对路径：换机器要重新配对；相对路径只按音色目录解析，别指望它跟权重目录相对。
6. 导入/配对默认不复制权重；要「目录自足」就在表单里选 `hardlink`（同盘，不占空间）或 `copy`（占空间）。
7. 硬链接/复制会把**原文件名**放进 `<id>/`：若用户把音色 id 改成与权重文件名推出的 id 不同
   （`klee-gsv-e10.ckpt` 放进 `<voicesDir>/klee2/`），扫描器按文件名会认出 `klee`，看起来就像多出一个音色；
   预览里对此有警告。想自定义 id 又不改名，就用默认的 `pointer`。

## 十五、音色导入改版（2026-11-15，破坏性：只剩音色包目录）

**起因**：§十四 的形态是「四个来源 + 指针放法 + 一张常驻的配对卡」。三件事在实机上都能感到别扭：
① 卡上永远横着一张六格表单，而导入是一次性动作；② 「这个音色为什么是灰的」有四五种答案（参考目录、
两个权重目录、`voice.json` 指针、`_default` 兜底）；③ 指针放法让「音色包目录」不同时是「能整包搬走的目录」——
换机器要重新配对。用户明确要求：**去掉「音色素材」面板，老音色配置不再兼容也不读取**。

**这一版的口径（唯一）**：

```
<voicesDir>/<id>/          ← 一个子目录一个音色，id 就是目录名
  ref.wav | ref.mp3 | …     参考音频（`ref.*` 优先；目录里只有一个音频时也认）
  ref.txt | <id>.txt | <ref 同名>.txt    参考文本（取第一段非空行；都没有 = 零样本）
  *.ckpt / *.pth            两侧权重，真文件（顶层或一层 `v2/` 子目录）
```

**删掉的东西**（老配置里残留的键既不读也不删，`readProviderValues` 只按 `fields` 白名单取值，不会回传）：

| 移除                                                                  | 影响                                                                                                                 |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `GsvSettings.refsDir` / `gptWeightsDir` / `sovitsWeightsDir`          | 权重目录只在导入时临时选一次；平铺参考目录不再支持                                                                   |
| `splitRoots` / `gsvSourceRoots` / `hasGsvSource` / `GSV_SOURCE_FIELD` | 必填项只剩「服务地址 + 音色包目录」                                                                                  |
| `<id>/voice.json` 全格式                                              | 不再有 `engine` 过滤、`desc`、`split`、`temperature/top_k/top_p/seed`、`prompt_lang` 覆盖、`gpt`/`sovits`/`ref` 指针 |
| `_default.wav/.txt` 兜底、`refsDir` 平铺源、权重目录扫描源            | `GsvVoice.source` 字段一起删；每条音色的来源只有一个                                                                 |
| `pointer` 放法、`target: 'refs'`                                      | 权重必须是真文件：`hardlink`（引用）或 `copy`；跨盘硬链接**直接报错**，不再偷偷退指针                                |
| `mode: 'scan'` / `'preview'` / 单条 `apply`                           | 改成 `weights` / `plan` / `apply` + `items[]`（1–50 条）                                                             |

**导入流程**（设置页 GSV 接入卡里的「导入音色…」，`Client/settings/voice-import.ts`）：

1. 「选择权重目录…」→ `mode: 'weights'` + `root`（`GPT_weights*` / `SoVITS_weights*` 所在那一层；
   选中的本身是这类子目录时自动上提一级；没有子目录但根目录直接放权重时两侧都用它）。
   宿主用自己的 `discoverWeightRoots` 展开、用自己的 `pairWeightsOf` 配对（**排序只有这一处真源**，
   与扫描器共用），返回逐行候选：`gptFiles`/`sovitsFiles`（全量候选，新到旧）、默认选中的一对、
   `bytes`、`linkable`（与音色包目录同盘）、`installed`。零写入。
2. 清单逐行：勾选（不勾不可编辑）→ 选参考音频 → 填/从文件挑一行参考文本 → 选「引用」或「复制」。
   多 epoch / 多版本的那一侧给下拉；只有一侧的行照样能勾（导完置灰，等补齐）。
   `linkable: false` 时「引用」`disabled`，行内写明「权重在 X、音色包在 Y：不能引用，只能复制（约 230 MB）」。
3. 「开始导入」→ `mode: 'plan'`（整批只读；任一条不合法就一条都不写，逐行标红）→ `mode: 'apply'`
   （逐条独立成败，整批只 rescan 一次）。结论行：`已导入 n · 跳过 m · 失败 k`，逐行给 `placed/notes`。

**为什么「引用」默认、跨盘默认改「复制」**：一套 v2 权重实测 230 MB，硬链接不占双份且是真文件；
但硬链接跨不了盘（实测 `EXDEV`），所以宿主把判定提前到扫描阶段（`sameVolumeOf` 比卷根，
正反斜杠混写也能判对），界面据此置灰选项，而不是让人点一次再读一条报错。

**实测（2026-11-15，临时目录）**：同盘 `hardlink` 后 `statSync().ino` 与源文件相等（真硬链接，未复制）；
`copy` 后 inode 不同、体积一致；已存在参考且未勾「覆盖」→ 只补权重、第二次返回 `skipped`；
勾「覆盖」→ 旧 `ref.wav` 改名 `.bak-<时间戳>` 后写新的；批量 3 条里第 2 条权重缺失 → `errors[0].index === 1`
且第 1、3 条照常写盘。`discoverWeightRoots` 四branch（父目录 / 子目录自动上提 / 根目录直放 / 空目录）均覆盖。

**测试**：`npm test` 3578 例 / 3576 过 / 2 skip / 0 败；新增 `voice-import.test.ts`（8 例：放法预选、
条目拼装、按钮与结构说明、弹窗开合与「音色包目录没配」），重写 `voices.test.ts` / `voice-pack.test.ts` /
`routes/voice-pack.test.ts` / `shared/voice-pack.test.ts`，`voice-provider-card.test.ts` 补 `beforeActions` 位置。

**升级动作（用户侧）**：设置页「声音 → 语音接入」→ 填「音色包目录」并保存 → 点「导入音色…」→
选 `GPT_weights` / `SoVITS_weights` 的父目录 → 逐行勾选并补参考音频/文本 → 选「引用」（同盘）→ 开始导入。
旧配置里的音色不会自动迁移：想让它们出现在菜单里，就得按上面的流程重新导一次（这正是「不再兼容」的意思）。

## 十六、四项现场修正（2026-11-18：结构说明 / 选择框 / 扫描按钮 / 桌宠总开关）

用户实际操作后提的四件事，逐条改动与验证如下。

### 1. 音色包目录结构说明：`*.ckpt` 与 `*.pth` 拆成并列两行

原来写成一行 `*.ckpt / *.pth`，读起来像「二者选一」；实际是**同级的两类文件**（`.ckpt` = GPT、`.pth` = SoVITS），
缺哪一份这条音色就合成不出来。现在五行：

```
<id>/        一个音色（导入时自动创建）
├─ ref.wav   参考音频（导入时复制；3–10 秒最稳）
├─ ref.txt   参考文本（可缺省，缺省 = 零样本）
├─ *.ckpt    GPT 权重（引用 = 硬链接，或复制）
└─ *.pth     SoVITS 权重（引用 = 硬链接，或复制）
```

字典键：删 `voiceImportTreeWeights`，加 `voiceImportTreeGpt` / `voiceImportTreeSovits`（8 语言）。

### 2. 「选择权重目录…」点了没反应 → 五条一起修

真机上 `FolderBrowserDialog` 的脚本里有一句 `$d.UseDescriptionForTitle = $true`，而它**只在较新的
.NET Framework 上存在**：实测本机直接报 `The property 'UseDescriptionForTitle' cannot be found` 并写进 stderr。
对话框仍然弹得出来，但由此引出几个「看起来没反应」的来源，全部修掉：

| 原因                                                                            | 修法                                                                                                                                                                                           |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 后台进程（宿主）弹的框默认开在浏览器**后面**，用户看不见                        | 给一个隐身 `TopMost` 属主窗体（`$o.Opacity = 0` + `ShowInTaskbar = $false` + `WindowState = 'Minimized'`），`$d.ShowDialog($o)`，结束后 `$o.Close()`                                           |
| `[Console]::Out` 被重定向时默认是控制台代码页（简中 = GBK），Node 按 UTF-8 解码 | 脚本第一条语句改成 `[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding $false`（目录框与文件框都加）                                                                              |
| 老机器没有 `UseDescriptionForTitle`，抛非终止错误                               | 删掉这一句（`Description` 本身就是对话框描述）                                                                                                                                                 |
| 机器上只装了 PowerShell 7（`pwsh`）没有 `powershell.exe`                        | `interpretersOf`：`powershell.exe` → `pwsh.exe` → `pwsh`，`ENOENT` / `EACCES` 时自动换下一个                                                                                                   |
| 前端只在 `unsupported && message !== ''` 时提示，宿主回个看不懂的响应就整段静默 | 任何非 `picked` / 非 `cancelled` 的结论都落到一句可操作的提示（`voiceImportPickUnsupported` / `voiceImportFilePickUnsupported`）；`/pick-folder`、`/pick-file` 的 `unsupported` 也写进宿主日志 |

更关键的结构改动：**权重目录改成一个可粘贴的输入框 + 「选择目录…」+ 「读取」**。
输入框是主入口，系统选择框只是懒人快捷键——弹不出来也永远有路走；`Enter` 与「读取」等价。
错误文案从弹窗页脚挪到**输入框正下方**（一个 message 状态两个落点：`!` 开头 = 输入框下，其余 = 页脚），
再也不会出现「原因写在弹窗最底部、用户以为没反应」。

### 3. 卡里加「扫描音色」按钮

音色包目录里的文件是用户直接在磁盘上加删的，而实现的扫描结果有软过期（`SCAN_TTL_MS`）。
新路由 `POST /voice/rescan { provider? }`：`provider` 缺省 = 扫全部第三方实现；实现没声明 `rescan` → `unsupported`；
有则 `await provider.rescan()`，结论一律**从注册表现取**（`voiceProviderStatuses()`，与 `/voice/voices` 同源）：
`{ ok, ready, total, notes }`。前端按钮显示「扫描中…」→「已重新扫描：可合成 n / 共 m」，
`ready === 0` 时把宿主给的第一条诊断接在后面（否则只剩一个 0，用户不知道差什么），并刷新下拉与右键菜单。

### 4. 桌宠全局开启关闭（`petEnabled`）

新顶层字段 `main.petEnabled`（默认 `true`），设置页「系统与桌面」第一个开关。语义是**一处关掉全部**：

- **桌面端**：`plugin/desktop/pets.ts` 的判定层读 `petsEnabled(merged)`，关掉时 `desktopPetList()` 为空、
  `getHasDesktopPet()` 为 `false` → Helper 干脆不拉起来；保存后走既有的 `requestRestart()` 重建。
- **网页端**：`client/pet/multi.ts` 用 `petsOn` 把渲染列表清空（这是页面上唯一的渲染入口）。
- **定时任务**：`effectivePetList()` 在总开关关掉时返回空（待办提醒因此没有可开口的宠物）；
  余额周期、碎碎念、梦话三个 `tick` 各自早退并留一行「总开关已关闭」的日志，周期照排，开回来立刻恢复。
- **不改 `display`**：`display` 是用户的显式配置，关掉总开关时不替他改任何一只宠物；开回来原样。

`use-global-settings.ts` / `config/read.ts` / `config/http.ts` / `dirty.ts` / `snapshot.ts` /

## 十七、避让静音与人设前缀（2026-11-18）

两条现场反馈，各自改一处判定。

### 1. 全屏避让时暂停语音 + 「全局隐藏 / 暂停」系统级快捷键

**避让静音**：桌面端的避让判定在渲染端（`runtime/electron-helper/sprite/avoid.js`，逻辑来自
`src/shared/avoid`），它每拍算出「藏 / 不藏」后让主进程 `win.hide()`。问题是窗口 `hide()` 之后
页面**还在跑**——自动播报会从一个看不见的宠物那儿突然念出来。所以 `hidden` 翻转时同步调用
`S.setVoiceAvoidPaused(hidden)`，与「全局暂停」分开记：

| 状态          | 谁翻                        | 语义                    |
| ------------- | --------------------------- | ----------------------- |
| `avoidPaused` | 避让看门狗                  | 全屏应用在前台 → 不出声 |
| `paused`      | 快捷键 / 托盘的「隐藏宠物」 | 用户主动要求安静        |

`src/shared/voice.ts` 里 `isVoicePaused() = paused || avoidPaused`，`playSayVoice` / `speakNotice`
两道门都先问它；任一暂停打开时立刻 `stopAutoAudio()`（暂停的意义是马上安静，不是把这句念完）。
手动点播（对话面板的喇叭）不受影响——那是用户的明确动作。两个布尔各自结束、互不覆盖：
避让结束不会解开用户按下的暂停，反之亦然。

**快捷键**：新增 `main.hideAllHotkey`（默认 `Control+Alt+H`，空串 = 关掉）。
为什么必须是系统级而不是第十个悬停裸键：**宠物藏起来之后页面上没有可悬停的东西**，
那一刻悬停键必然按不到——而这条快捷键的用途恰恰是「藏起来之后还能按回来」。

- 解析与判定在 `src/shared/hotkeys.ts`：`parseGlobalHotkey` / `normalizeGlobalHotkey` /
  `matchesGlobalHotkey` / `globalHotkeyCap`。规则：`+` 分段，最后一段是主键（字母/数字/F1–F12），
  前面全是修饰键，**至少要一个修饰键**（裸字母做系统级快捷键会抢走所有输入框的那个字母）；
  别名收成规范名（`ctrl`→`Control`、`cmdorctrl`→`CommandOrControl`、`meta/cmd/win`→`Super`）。
- 桌面端：`runtime/electron-helper/main/shortcut.js` 用 `globalShortcut.register` 注册，
  注册失败（被占用）只记一行日志——托盘里还有等价入口。一次按键做两件事：
  `windows.setHidden(!isHidden())` + `broadcastCommand('pause'|'resume')`；渲染端收到命令后
  `S.setVoicePaused(...)`。配置在 `main.js` 的 `whenReady` 里读一次（配置改了宿主会重启进程），
  `before-quit` 注销。`windows.js` 新增 `isHidden()`，让托盘勾选态与快捷键读同一个值。
- 网页端：`client/pet/multi.ts` 在 `window` 上听同一串组合键（没有系统级快捷键可注册）。
  隐藏靠渲染门 `petsOn && !hiddenByKey`，暂停走同一个 `setVoicePaused`——
  组件返回 `null` 时**依然挂载**，所以再按一次就能恢复，不会变成单向操作。
- 设置页：`shortcuts-card` 新增「全局隐藏 / 暂停」一行——文本输入框（写错就地提示，不等保存失败）
  - 「恢复默认」；空串时明确写「已关闭」。改动随「保存」落盘，并计入「需重启窗口」提示
    （`restart-hint` 的 `hideAllHotkey`）——换键位必须重启 Helper 才会重新注册。

### 2. 人设输入框开头多出的「人设：」

不是前端自动加的，是**人设卡投影**时给每段都戴了标签：`persona-source/card-reader.ts` 的
`projectCard` 原来对 `description` 也拼 `${label}：`，于是第一段变成 `人设：鱼生，叫鱼生…`，
同步进 `pets[].whisperPrompt` 之后，设置页那个输入框看起来就像系统往里塞了个前缀。

改法：**只有第一段不戴标签**（`sections.length === 0 ? text : `${label}：${text}``），
后续段（性格 / 背景 / 开场白 / 对话示例）照旧——它们本来就需要标签区分。
段落顺序固定，读到第一段不用靠标签也能知道那是人设。

已同步过的配置不会自己改写：人设来源还在（卡片文件可读）时，下次启动或卡片变化触发的同步会重写一遍；
否则在输入框里把开头那几个字删掉即可。
