# 设置页 UI 重构（2026-11-14）

> 对象：DSH 插件设置页「桌宠配置」（`settings.section` / `pet-config`，源码 `dsh-pet/src/client/settings/**`）。
> 非目标：`src/standalone/settings-page/**`（独立模式那套脚本页）、桌宠渲染、对话面板、host 半侧、配置 schema 与路由。
> 本文记录这一轮的决定与依据，便于下一轮接手时知道「为什么长这样」，也便于回滚。

## 一、一句话方向

从「七个分区、四十个问号、三排选中条、四个底部按钮」收敛成 **6 个分区、一套控件规格、卡片内分小节、一个保存栏**：
层级靠留白与字重，不靠边框、问号与常显小字；常用项前置，维护动作沉底。

## 二、信息架构

| --- | -------- | ---------- | ----------------------------------------------------------------------- |
| 1   | `pet`    | 桌宠       | 种类下拉 + 实例 chip + 单卡（身份 / 显示与位置 / 功能 / 人设折叠）      |

## 四、加上去的东西

1. **撤销改动**：底部栏在 `busy` 之外多一个「没有改动就禁用」的按钮。实现是重新拉配置与会话鱼（复用加载链路），
   而不是本地回滚快照——快照回滚要维护第二份「路径 → 控件状态」的映射，重读天然与基线一致。
2. **未保存条数**：底部栏左侧只有一条状态（有保存结论就显示结论，否则显示「未保存 n 项」）。
3. **卡片内小节**：`section()` 提供第二层分组（只有相邻小节之间画 1px 分隔线），避免整页变成卡片汤。
4. **折叠**：移动端效果、每种渲染方式的大小、音效来源与命名、token 成本说明、人设——默认收起，展开即全量信息。
5. **来源徽标**：音效槽位的来源（内置默认 / 皮肤 / 未匹配…）缩成一枚小徽标，未匹配带告警色。

## 五、视觉与交互规格

- 尺度：间距 4 / 8 / 12 / 16；控件 28px 高、圆角 8px；卡片圆角 12、内边距 14×16。
- 字号：标题 14/500、正文 13、标签 12、元信息 11；标题 `letter-spacing: -0.01em`。
- 颜色：全部取 `--dsw-*`（`settings-card-fill/stroke`、`state-business-primary`、`switch-thumb`、`button-info-fill`…），
  缺 token 时按 `var(--dsw-x, fallback)` 回落；没有字面色值（主题色与深色模式由宿主决定）。
- 开关：34×20 轨道 + 16 圆点（真节点，`transform` 位移 14px），视觉是开关、语义仍是 `checkbox`（这些开关随「保存」整包落盘，不是即时生效）。
- 分段标签：一条轨道 + 选中块（`button-ghost-active-fill` + 内描边），等宽；窄容器（≤400）折成两行而不是横向滚动。
- 动效：分区内容入场 160ms（透明度 + 6px 位移）、折叠 `grid-template-rows` 160ms、开关 120ms、按钮按下 0.98/80ms；
  `prefers-reduced-motion: reduce` 把动画与过渡压到 1ms。
- 响应式：容器查询 600px（四列降两列）与 400px（全部单列、头像回到 72px 方块、底部栏按钮平分）。

## 六、保存语义（未改）

否则会出现「文件缺字段但页面看着干净所以没写」的边角）。控制台快捷键 `Ctrl+S / Cmd+S` 仍等于「应用」。

## 九、真机验收回归（同日 08:1x 之后，两轮）

第一轮真机验收报上来的三处问题，逐条定位与修法：

1. **开关点了圆点不动**。两层原因叠加：
   - 圆点原来画在 `input::after` 上——`input` 是替换元素，伪元素不保证生成、也不保证跟着 `:checked` 重新布局；
   - 更要命的是「减少动画」降级块里写了 `transform:none!important`（`.dsh-pet-cfg *`），
     而圆点位移**承载的是状态**：系统开了「减少动画」时，开关被压成「只会换色的色条」，开和关长得一模一样。
     现在：圆点是真节点（`span.swTrack` + `span.swKnob`），透明 `input` 铺在轨道正上方负责语义/点击/键盘/读屏；
     降级块只压时长，不再动 `transform`。真机实测（`prefers-reduced-motion: reduce`）：开 → 圆点偏移 16px，关 → 2px。
2. **「打开文件夹」点了没反应**。原因是 Windows 那一步用 `powershell -Command Start-Process`：
   宿主是以**隐藏窗口 + detach** 拉起子进程的，`STARTUPINFO` 里的 `SW_HIDE` 会顺着 `Start-Process`
   传给目标进程——目录确实打开了，窗口永远是隐藏的。实测把同一发 ShellExecute 换成
   `rundll32.exe url.dll,FileProtocolHandler <目录>`（GUI 子系统、无控制台、跟随默认文件管理器）后，
   窗口正常出现。`explorer.exe` 兜底那一路必须 `windowsHide: false`，否则同样拿到隐藏窗口。
3. **音效没开时也应能试听**。原先解析结果把「开关关着」和「没有文件」都收成 `null`，设置页据此判两件事，
   于是「关掉开关」被误读成「未匹配」、试听也跟着消失——想先听一遍再决定开不开就做不到。
   现在两个口径分开（见 `settings/sfx-view.ts`）：checkbox 读配置里的真实开关，来源徽标与试听读
   「开关全开」的预览视图，试听的门槛只有**有没有匹配到文件**；`trySlot` 也走预览口径，所以真的会发声。

验证：真机 Playwright 复验（`reducedMotion: 'reduce'` 下圆点位移、开关关掉后徽标仍是「内置默认」且试听可点可响、
`/open-folder` 之后确实多出一个文件管理器窗口）；`npm test` 3206 通过、`npm run test:ui` 71 通过（新增两条：
两种动效偏好下的圆点位移、关开关后试听仍在），`typecheck` / `lint` / `format:check` / `check:cycles` 全绿。
顺带把 `artifacts/` 加进 `eslint` 与 `prettier` 的忽略表：那是验收截图与一次性探针脚本的落点。

## 十、第三轮：圆点居中与「改动项自己带标记」

1. **圆点在开关里偏上**。两个原因一起改：
   - 垂直位置原本写死 `top:1px`，在 125% / 150% 这类小数像素缩放下会向上取整，看着就是偏上——
     改成 `top:0;bottom:0;margin:auto 0`，让浏览器按剩余空间平分；
   - 圆点直径 16 在 20 高的轨道里只剩 1px 轨道底色，和轨道描边糊成一片（也加剧了「偏上」的观感）——
     直径收到 14（内容 12 + 1px 描边），上下各留 2px 底色。
     真机实测：轨道 20 / 圆点 14 / 上留白 3 / 下留白 3（含描边）。
2. **改动项自己也要有标记**。原来只有卡头与标签条有圆点，改到哪个开关还得自己找。现在：
   - `ui.field(...)` 与 `ui.toggleCell(...)` 多收一个**配置路径**，`DirtyQuery.has(path)` 命中时给容器挂
     `is-dirty`、并在标签文字后跟一颗 6px 圆点（`.dsh-pet-cfg__dot.is-inline`），标签同时升到主色 + 500 字重；
   - 每个调用点都接上了自己的路径（`global.*` / `voice.*` / `model.*` / `look.physics.*` / `look.weights.*` /
     `look.font.*` / `fish.*` / `sfx.events.<槽>` / `sfx.hooks.<名>` / `pets.<下标>.*`）；
   - 为此 `diffSnapshot` 的数组改成**按位置下钻**（`pets.0.size`）：宠物卡才能分辨「改的是大小还是名字」。
     长度一变（加/删宠物）仍然退回聚合路径 `pets`，那种情况下「哪一项变了」本来就没有意义。
     真机实测：改「大小」只有大小那格亮；再改「碎碎念」只有那一个开关亮；其它格保持干净。

落地位置：`ui.ts`（`field` / `toggleCell` / `switchNode` 的 `path`）、`dirty.ts`（数组下钻）、
`style/cards.ts`（`is-dirty` 与行内圆点）、`pet-card-parts.ts` / `pet-card.ts`（宠物字段路径）、
`sfx-slot-row.ts` / `sfx-hooks.ts`（槽位与 hook 行）。UI 套件新增一条：改一个开关 → 该格 `is-dirty` + 一颗点 + 字重 500。

## 十一、第四轮：两张「落盘位置」卡合并成一张「文件与目录」

起因是三个问题一起问到了同一处：系统分区最后两卡（4 高级配置（文件） / 5 卸载与存储）都在列路径。
查下来重复不在字面上，而在**信息结构**上——父目录与子目录各列一遍（5 的 `userData` 就是 4 里
`animations/memes/pool/todos/logs` 的父亲），而真正会丢的东西（`data/memory.json`）反而没列。

### 决定

| 问题                       | 决定                                                                                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 4 要不要去重 / 去掉        | **合并去重，不整块删**。它是产品内唯一「我的文件在哪」的入口（`logs.txt` 排障不可替代）；删掉的是重复表达与两段与「位置」无关的长 hint。       |
| 要不要新增「目录结构」面板 | **不新增**，直接与 4 合并成一棵树。拆成「路径列表 + 说明面板」= 一次查询两次点击；素材命名规则（怎么做一个皮肤）留在 `CONFIG.md`，不进设置页。 |
| 4 与 5 的合并形态          | 一张折叠卡，四个小节：**数据根 → 目录结构 → 运行时 → 卸载**。一条路径只出现一次；能不能删用徽标（`可删` / `需下载`）说；破坏性动作沉底。       |
| 树从哪来                   | 宿主生成（`/config/meta` 的 `layout` / `readonly`），客户端只按 `depth` 画 `├─ / └─`。目录布局怎么改，卡片一行不用动。                         |

### 顺手解决的

- `data/memory.json`（对话记忆）以前完全没展示，现在在树上；
- 「运行时」从「存储清单里的一行」升成**有状态、有动作**的一节：已安装 vX / 未安装 + 「下载运行时」
  （`POST /desktop/runtime`，幂等，界面 2.5s 轮询），并把 `runtime/` 与 `cache/` 分开——删 cache
  不该逼用户重下 350 MB；
- 目录本身带说明：启动时给每个目录写 `desktop.ini` 的 `InfoTip`（`host/folder-note.ts`），
  Explorer 的「备注」列直接显示「这个目录是干什么的、能不能删」。

### 新契约

- `GET /config/meta`：`root` / `layout[]` / `readonly[]` / `runtime` / `package`；**`storage[]` 删除**。
  `layout[]` 每项 `{ key, rel, name, path, kind, depth, exists, open?, badge? }`（扁平 + depth）。
- `POST /open-folder?which=`：新增 `root/config/data/cache/runtime/pets/assets`；旧值保留。
- `GET|POST /desktop/runtime`：运行时状态与下载触发。
- 新增 i18n 键 15 个（`fs*`），删 18 个（`configMeta*` / `storage*` / `defaultConfig` / `userConfig` /
  `animationDir` / `memesDir` / `poolDir` / `todosFile` / `logFile*` / `storageMissing`）；
  `uninstallCmd` 的包名改成 `dsh-fish-body`，`uninstallStep3` 改成带 `{root}` 的可执行版本。

## 十二、第五轮：徽标退场、`pet`/`skin` 正名、位置可改、运行时按需弹窗

第一轮把「能不能删」做成徽标，这一轮把那条路**整体撤掉**——不是样式问题，是那句话本身不可靠：
语音缓存在断网时可复用、安装包缓存在镜像抽风时能救急，「可删」在真实场景里经常不成立。
同时用户提出四件事：说明写在行上、位置要能改、`pet` 与 `skin` 的含义反了、运行时缺失要看得见。

### 决定

| 问题           | 决定                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 徽标           | **删掉 `disposable` / `download`**。树每行名字后面跟一句「这个目录存什么」（`fsDesc.<node key>`，8 语言），漏登记的节点只显示名字。只读参考那一组的 `只读` 徽标保留——那条是「不能改」，不是「能不能删」。                                         |
| 文案           | 用户可见文案里不再出现「可删 / 随时删 / 删了没影响」；`cache/*` 只描述存了什么。`LAYOUT_NOTES`（desktop.ini 备注）同步改成名词性描述。                                                                                                            |
| `pet` / `skin` | 含义互换：`assets/pet/` = 内置皮肤池（共用的那份），`skin/` = 用户自己的皮肤（一个 pack 一套）。迁移时 `<根>/skin` 只在「长得像池」时才搬进 `assets/pet`，否则它是用户皮肤，一个文件都不动。                                                      |
| 位置           | 数据根、用户皮肤目录各有「更改位置…」：原生选目录框（宿主侧弹，Win/mac/Linux 各用系统自带）→ 确认 → 后台复制（带进度）→ 核对文件数与字节 → 通过才删旧位置 → 「重启后生效」+ 立即重启。                                                            |
| 运行时         | **保留自动下载**（行为不倒退），新增：国内镜像链（`cdn.npmmirror` → `npmmirror` → GitHub）、下载进度、缺失弹窗（`prompt.reason = missing/deleted/failed`）、「用已下载的目录…」。用户手删 `runtime/` 之后，下一次读状态就会把提示置成 `deleted`。 |

### 新契约

  （`fsBadgeDisposable` / `fsBadgeDownload`）。

## 十三、第六轮：树根顶格、迁移说明步、快捷键可改绑

四条反馈一次性落地（提交 `style` + `feat` 两个）。

### 1. 目录树根行不再缩进

`fish-body/` 那一行原来跟着 `└─ ` 一起画，整棵树被右移三格、与卡片左边缘对不齐。现在
`treePrefixes()` 对 `depth === 0` 直接给空串，祖先列从第 1 层算起：

```
fish-body/   插件的数据根，下面这些目录都在它里面。
├─ config/   设置：主配置、会话鱼、语音接入。
│  ├─ config.jsonc   …
└─ logs.txt  运行日志，排障时看它。
```

- 客户端：`client/settings/tree.ts` 跳过 0 层；`fs-card.ts` 的根行不再渲染前缀格子并加 `is-root`；
  样式把该行换成少一列的网格（`style/cards.ts` 的 `.dsh-pet-cfg__treeRow.is-root`），名字才真的贴住左边缘。
- 前提写进注释：一次渲染只允许一个根（`layoutNodes()` 就是唯一根），多根会把两棵树的枝干并排画。
- 测试：`tree.test.ts` 改成「根行空前缀」契约（6 条），`fs-card.test.ts` 断言根行无前缀、首个子项 `├─`。

### 2. 更改位置先说清楚「会迁移」，再动手

原来点「更改位置…」直接弹系统选目录框，而「会整体迁移」这句话只出现在选完之后。现在是三步：

1. **说明步**（点按钮立刻出现）：`要把「数据根/皮肤目录」搬到哪里？` + `旧：{路径}` +
   `{N} 个文件 · {体积}`（`GET /layout/size`，统计中显示占位）+ 一句「整体迁移，不是留一份副本；
   先复制、核对文件数与字节数，通过后才移除旧位置，失败两处都保留」；动作：
   `选择新目录…` / `直接填写路径` / `取消`。
2. **确认步**：弹窗把 `旧：` / `新：` 两条路径并排摆出来，附体积与「迁移完成后需要重启插件」；
   动作：`开始迁移` / `重新选择` / `取消`。
3. **进度 / 结论**：`已复制 {done}/{total} 个文件 · {体积} · {当前相对路径}`；搬完给「立即重启」。

- 宿主：`host/move-tree.ts` 导出 `dirSize()`（复用搬迁用的 `scan`，不跟随符号链接、不建目录、不写文件）；
  新增 `GET /layout/size?which=root|skin`（目录不存在回 0，`which` 非法 `bad-request`）。
- 客户端：`layout-api.ts` 加 `fetchDirSize`；`fs-card.ts` 的 `EditState` 加 `intro` / `picking` 两步，
  搬迁进度单独 `moveProgress` 状态（每拍刷新文件数与当前路径）。

### 3. 悬停快捷键写进配置、可在设置页改绑

九个键（对话 / 按住说话 / 截图 / 待办 / 睡觉 / 四个显示位置）从「写死的常量」变成 `main` 条目顶层的 `hotkeys`：

```jsonc
"hotkeys": { "chat": "l", "hear": "m", "capture": "s", "todo": "d", "sleep": "z",
             "display.web": "1", "display.desktop": "2", "display.both": "3", "display.none": "4" }
```

- **唯一真源** `shared/hotkeys.ts`：动作白名单、出厂值、`normalizeHotkeys`（齐全 / 合法 / 唯一）、
  `hotkeysValid`（写盘前整段校验）、`assignHotkey`（同一个键给了两项时**互换**）、`hotkeyHint`（键帽文案）。
- **判定跟着配置走**：`isChatHotkey` / `isCaptureHotkey` / `isTodoHotkey` / `isSleepHotkey` /
  `displayOfHotkey` / `createHearHold` 都接受 `HotkeyMap`（缺省走出厂值，签名向下兼容）；
  宠物卡每次按键现读 `cfgRef.current.hotkeys`，所以保存后立刻按新键生效，不必重建监听。
- **键帽不再有第二份**：`*_HOTKEY_HINT` / `DISPLAY_HOTKEY_HINTS` 常量删除，菜单与设置页统一走
  `hotkeyHint(map, action)`；桌面端右键菜单的「显示位置」子菜单也从 `flattenConfigPets` 吹进来的
  `Pet.hotkeys` 取同一份。
- **只支持裸键**：带 Ctrl/Alt/Meta 的组合属于浏览器（复制 / 撤销 / 切标签），宠物去抢会抢坏基本操作。
- **设置页**：「系统 → 快捷键」卡分三组——宠物自己的键（5 行，可改绑）、显示位置键（4 行，可改绑）、
  全局命令（5 行只读，改绑在「设置 → 通用 → 快捷键」）。点键帽进捕获态（`按一个键…`），
  按一个裸键即写入、`Esc` 取消；卡里有「恢复默认键位」；改绑走「未保存改动」圆点，随底部栏保存。
- **写盘**：`host/config/save.ts` 把 `hotkeys` 纳入白名单（非法整包拒绝、合法归一后落盘、未传透传旧值）；
  `shared/config.ts` 的 `flattenConfigPets` 把它吹进每只实例（含文件宠物），网页端与桌面端因此同源。
- **默认配置**：`assets/config.jsonc` 新增带注释的 `hotkeys` 段；顺手把 `assets.pool` 的默认值从
  `assets/skin` 改成 `assets/pet`（旧值仍会被归一，但默认值不该每次启动都触发一条 legacy 提醒）。
