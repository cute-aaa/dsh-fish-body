## 一、一句话现状

云端 TTS 从「骨架」变成真的 DeepSeek 实现（`POST /v1/tools/tts`），但它**永远不进自动回退链**：
链只保留不花钱的实现（本地 GSV → 在线 edge），DeepSeek 只在用户打开 `useCloud` 时被显式排到链首，
自己失败就回落免费链。设置页接入卡现在支持 `select` 字段（`useCloud` / `voice` 两个下拉）。
动画与点击音效在原代码里本来就完整，本轮只做验收，没有改播放器。

## 三、唯一事实表：免费链 vs 付费来源

| 项       | 值 / 规则                                                                                                                          |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 免费链   | `voiceChain()` = 可用的 `billable !== true` 第三方（注册顺序）→ 内置 `edge`。GSV 是本地服务，edge 免费                             |
| 付费实现 | `VoiceProvider.billable === true`（目前只有 `cloud`）。**`available` 为真也不进链**                                                |
| 显式来源 | `voiceChainWithPreferred(preferredId)`：付费实现可用时排**链首**，其后接免费链                                                     |
| 开关来源 | `<userRoot>/config/voice-providers.json` 里 `cloud.useCloud === 'on'`（`speak()` 每次合成现读）                                    |
| 失败行为 | 首选失败 → 落免费链，日志 `link cloud failed` + `fell back to edge`；失败请求不计费                                                |
| 首选失效 | 未注册 / 非付费 / 不可用 → 静默当没选，另留一行 `preferred <id> unavailable, using free chain`                                     |
| 缓存范围 | 链内每环 + 全部免费实现（含此刻不可用的）+ 内置；**付费实现不在链上时不查它的缓存**（否则关掉开关还会有云端嗓子）                  |
| 云端字段 | `useCloud`（`off`/`on`，默认 off）· `baseURL`（留空 = `https://api.deepseek.com`）· `voice`（`stella`/`tide`）· `apiKey`（凭据库） |
| 密钥     | 主引用 `DSH_FISH_BODY_CLOUD_TTS_KEY`；只读回退 `DEEPSEEK_API_KEY`（`credentialFallbacks`）。保存/清除只动主引用                    |
| 探活     | `refresh()` 只判「地址合法 + 能拿到 key」，**不发请求**；注册后跑一次，`/voice/provider-config` 保存后再跑一次                     |

## 四、数据链（按顺序读这一节就能改）

### 4.1 开关怎么传到合成

```
voice-providers.json 的 cloud.useCloud
  → index.ts 的 createVoiceService({ preferredProvider })
  → speak.ts 每次 speak() 现读 → voiceChainWithPreferred(preferredId, synthesizeImpl)
  → chain.ts：preferred 指向 billable+available 的实现时排链首
  → synthesizeAlongChain：成功即返回，失败落下一环（免费）
```

`preferredProvider` 读配置可能抛（文件写坏）：`speak.ts` 里 try 住，抛了就当没开，
不让一个开关把整句话打断。

### 4.2 云端 synthesize 契约

```
POST {baseURL || https://api.deepseek.com}/v1/tools/tts
authorization: Bearer <key from credentialRef → DEEPSEEK_API_KEY>
body: { text, voice_id: 'stella'|'tide', format: 'wav', filter_markdown: true }
signal: AbortSignal.timeout(12_000)      // chain 外层 15s
200 → { data: Uint8Array, mime: 'audio/wav' }
非 2xx → 读 error.message（截 512 字符）→ lastError + 抛错
< 44 字节 → 视为空音频失败
```

`rate` 被忽略（接口不支持），不抛错、不刷日志。

## 六、踩坑（编号续 P4 的 49）

50. **付费实现绝不能进自动链**：「哪个实现可用」与「用户愿意为它花钱」是两件事。把云端放进链，
    本地服务没起的那天起，每句话都在静默计费；而链的设计初衷恰恰是「本地挂了也照样有声」。
    正确切法是 `billable` 标记 + 只在显式开启时排链首，失败回落（失败请求不计费，所以回落不增加成本）。

51. **同步的 `availability()` 遇上异步的密钥**：registry 契约要求同步探测，但 key 在凭据库。
    解法同 GSV：探活结论缓存进 `verdict`，`refresh()` 异步更新。**探活绝不能发请求**——
    TTS 没有免费 ping，拿一句话去试就是一次计费；只判「地址合法 + 能拿到 key」。

52. **流式 wav 的 size 字段是 `0xFFFFFFFF`**：DeepSeek 边合成边返回，无法定长，RIFF 与 `data` 两个长度字段都写满 4 字节。
    Chromium（网页端 `<audio>` 与 Electron 同一套 demuxer）实测能正常播到结尾（`loadedmetadata` → `canplaythrough`
    → 4.44 s 播完），**不需要回填**。ffprobe 也能解。要更保险可按真实长度回填（`RIFF=len-8`、`data=len-44`），
    写法验过，但不是必需——别为此在上传路径上加一次全量拷贝。

53. **这个接口没有 model、没有语速、没有 mp3**：`model` 字段照着 OpenAI 兼容的想象留着，只会永远判「缺必填」→
    永远不可用；语速参数传了也没人看，界面却会让用户以为「拖了没生效是 bug」——所以 `rate` 直接忽略，
    并在 `voice` 字段描述里写明。`format` 只能取 `wav`/`pcm`，`pcm` 是裸流（无容器），缓存扩展名表与 `<audio>` 都不认。

54. **wav 比 mp3 大约 8 倍**：同一句 30 字，wav 213 KB / 48 kbps mp3 27 KB。缓存上限 20 MB / 200 文件，
    换成 wav 只能存约 100 句（mp3 约 700）。短句重复率高，命中率掉下来就是反复计费；本轮不改上限，靠 LRU，
    真觉得贵再考虑 WS `format=opus`（返回裸 Opus 包，要自己封 Ogg 容器 `<audio>` 才认，不是小改）。

55. **`credentialFallbacks` 必须是只读**：设置页「清除」按钮若顺着回退引用清下去，用户点一次
    就把整个 DSH 的模型凭据删了。写入与清除永远只动 `credentialRef` 指向的那一项；
    「配没配」可以是主引用或任一回退在场（这正是「复用 `DEEPSEEK_API_KEY`」的意义）。

56. **缓存要按「本次链里的来源」查**：`cacheOrigins()` 原来遍历全部注册实现。云端合成过的句子会留在
    付费 origin 的键上，关掉开关后仍会被命中——用户听到云端嗓子，会以为「关不掉」。现在付费实现只有
    在链上时才参与缓存查找；免费实现（含此刻不可用的）照旧全查，保住「本地服务挂了用旧音频顶上」的语义。

57. **`select` 字段的两个必做配套**：客户端 `options` 为空时必须退回输入框（渲染空下拉等于给用户一个死控件）；
    宿主侧路由要按 `options` 校验取值——不在候选里的值写进配置，界面上会显示成空，用户以为没保存成功。
    `VoiceFieldView` 之前把 `options` 丢掉了（host 声明有、客户端解析没读），这次一并补上。

58. **`form: desktop` 时网页端不渲染宠物**：想用 playwright 点 `.dsh-pet-hit` 验点击音效会拿到「没有这个元素」，
    那不是 bug。要验点击只能对桌面窗口做真实点击（或用 `DSH_PET_DEBUG_CLICK=1` 重启 helper 让它自己模拟一次）。

## 十、`assets.resourceDirs`：多素材根（2026-11-15 补做）

### 10.1 语义

```jsonc
"assets": {
  "pool": "assets/pet",
  "resourceDirs": ["D:/AI/FishChi/body/skins"]   // 绝对路径或相对数据根；最多 8 条
}
```

- **顺序即优先级**：主池根永远第一，其后按数组顺序。同 id 资源先到先得，重复的一次 `warnOnce`。
- **两种布局都认**（只对 `resourceDirs`）：
  - 标准池布局：`<根>/layered|live2d|webm|sound`（有任一渲染方式子目录即判定）；
  - 皮肤集合目录（bare）：`<根>/feiyu-01/manifest.json` —— 一级子目录本身就是一套皮肤。
    主池根**只认前者**：否则 `assets/pet/*` 里的杂目录会被当成皮肤扫进来。
- 同一个目录写两遍、或与主根相同，会被去重（Windows 大小写不敏感）；路径不存在只是少一个根，不报错。
- 手改配置即可，**设置页目前没有这一项**（与 `assets.pool` 同档次：属于机器级路径设置）。
- 生效时机：每次请求现读配置，改完刷新即可（不用重启）。

### 10.4 已知限制

- **根级音效目录仍只取主根**：`<根>/sound`（池全局）与 `<根>/<渲染方式>/sound`（渲染兜底）的查找仍按主池根；
  外部根的皮肤**自己目录里**的音效（`<结构基名>-click.wav`）是生效的，因为那走「资源目录」这一级。
- 设置页没有这一项；`resourceDirs` 变化后要刷新页面（客户端有音效索引缓存，宿主侧现读）。
- 不做文件监听：放完文件刷新即生效，这是刻意设计（池是用户随时会改的目录）。

### 10.5 踩坑（续 §六 的 58）

59. **额外根不能默认要求池布局**：用户手里的皮肤库几乎都是 `<根>/<皮肤>/manifest.json`，要求先套一层
    `layered/` 等于让人搬文件；而主池根必须严格要求，否则 `assets/pet` 下的杂目录会被当成皮肤。所以「布局」
    是每个根的属性，不是全局开关。

60. **清单与取文件必须共用同一根序**：`/skins` 走合并扫描、取文件走候选目录，两处顺序一旦不一致，
    表现就是「清单里有这套皮肤，点下去 404」。`poolLayerDirs` 与 `readPoolRootsOf` 都从 `layoutOf` 取布局，
    就是为了让它们没法各说一套。

61. **`scan.ts` 该拆了**：单根布局 + 多根顺序 + 读盘探测塞在一个文件里会同时撞行数上限与可读性。
    现在是 `probe.ts`（这盘上有什么）× `scan.ts`（一个根长什么样）× `roots.ts`（多个根谁先谁后）。
    另外：按行号裁剪文件时别把 `interface` 的闭合括号一起删掉——编译器报的是 `Property or signature expected`
    （指向后面几百行），不告诉你少了个 `}`。

## 十二、「需重启插件后生效」的提示（2026-11-15）

改到「要重建桌面窗口」的设置时，网页端保存完看不出任何变化——用户只会以为保存失败。现在分两处说：

1. **改动那一刻**：字段 / 开关下方出现一行「需重启插件后生效」。判定在 `settings/restart-hint.ts`，挂的是
   `dirty.ts` 产出的**改动路径**（`pets.0.renderer` 这类快照位置），不是控件——卡片以后加字段、换排版都不会漏提示。
2. **保存之后**：底部栏出现「其中 n 项需重启插件后生效」+「立即重启」（与维护卡同一个 `restart({ save })`）。
   重启真的生效后计数清零；`hmr` 模式页面本来就会刷新。

覆盖范围（A 方案）：`pets`（增删）、逐宠 `renderer` / `model` / `display` / `size` / `sizePercent` / `fixedEnabled` /
`sizes.*`、`global.confineToScreen` / `global.trayEnabled` / `global.notificationsEnabled`。
三个对话开关（配图 / 动作联动）**不在**表里：它们在宿主每次生成时现读，加提示只会训练用户忽略提示。

`CONFIG.md` 顶部那句「点保存即时生效」已相应改写；`fs-card` 原有的「重启插件后生效 / 立即重启」（数据根 / 皮肤目录迁移）保留，并改为走同一个重启实现。

实机验收（2026-11-15，fish / 3099，真实设置页 Playwright）：

| 步 | 操作 | 结果 |
| --- | --- | --- |
| 1 | 打开「设置 → 桌宠配置 → 系统」 | 分区标签仍是六个（桌宠 / 外观与手感 / 声音 / 对话 / 会话鱼 / 系统） |
| 2 | 读卡片顺序 | `系统与桌面 → 看屏幕与避让 → 快捷键 → **维护动作**（备份与恢复 → 文件与目录 → 插件维护）`，分组标题命中 1 次 |

### 13.3 踩坑（续 §十 的 61）

62. **重启只能有一个实现**：「要不要先存盘」必须是一个显式参数，而不是两条各自生长的代码路径。两条并存时，
    一条会提示四种结论、另一条失败了什么都不说——用户看到的是「有时有反应、有时没有」。
63. **维护动作不插在设置项中间**：备份卡曾经夹在屏幕卡与快捷键卡之间，读起来像「系统通知的下一步」。
    分组比排序更有用：一个 `section` 标题就把「这组是配一次就不动的」讲清了。
64. **打开目录先问再建**：`openFolderOf(which, petId, /* create */ true)` 看着省事，代价是「莫名其妙多出一个空目录」
    且失败无人知晓。设置页四处入口现在共用 `FolderButton`，那套「先打开 → not-found → 问 → 创建再打开」只有一份。
65. **「需重启」挂在改动路径上，不挂在控件上**：挂在控件的 `path` 参数上省事，但没传 `path` 的字段（例如皮肤 / 模型选择器）
    就永远不提示；而 `diffSnapshot` 的路径是配置位置，天然覆盖全部字段。代价是新增「要重建窗口」的字段必须在
    `restart-hint.ts` 里登记一条（有单测钉着前缀与通配边界）。
66. **快照永不覆盖，恢复前先自拍**：覆盖式快照最危险的情况恰好出现在最需要它的时候（同一分钟内连拍两次、回滚命令按了两次）。
    id 撞了直接失败、恢复前先拍 `pre-restore`，两条都很便宜，却把「回不去了」这件事变成可逆的。
