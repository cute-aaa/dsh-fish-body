# 隔离用户场景验收记录（2026-11-26）

本轮目标是按真实用户路径验证“下载/安装 → 打开设置 → 导入资源 → 接入 soul / memory → Web/桌面使用”，
并确认设置页能完成这些动作而不需要改两边代码。

## 环境

- 系统：Windows
- Node：24.22.2
- pnpm：10.31.0
- 临时 `DSH_HOME`：`%TEMP%\dsh-fish-live-20261126-005002`
- 独立 profile：`e2e`
- 独立端口：`3199`
- 外部实例保护：3080 / 3081 / 8790 的 PID 验收前后均为 `44180`；未触碰 3099

## 安装链

1. `npm run build` 生成 `lib/`、类型声明、桌面共享核心。
2. `npm pack --ignore-scripts` 生成 `dsh-fish-body-0.6.1.tgz`。
3. 在临时 `DSH_HOME` 执行：

   ```text
   node D:\NodeJs\node_modules\@deepseek-ai\dsh\lib\bin.js plugin --profile e2e add <tarball>
   ```

4. profile 初始只有 base + 插件；补上 `@deepseek-ai/dsh-web-app` bundle 后，
   `--dump-config` 同时显示 web app 与 `dsh-fish-body`。
5. 启动方式：

   ```text
   node D:\NodeJs\node_modules\@deepseek-ai\dsh\lib\bin.js --profile e2e --port 3199
   ```

   首次真实页面出现过一次 import failed，根因是新共享模块把 zod 带进 classic-script client bundle。
   已把 schema 迁回 host-only 模块，重新构建后 `lib/client.js` 回到纯 IIFE，页面正常加载。

## Web 设置页

导航路径：

```text

```

实测结果：

- 六个分区均出现：桌宠 / 外观与手感 / 声音 / 对话 / 会话鱼 / 系统。

- 系统 → 兼容与记忆切到「自定义目录」后：
  - `config/integrations.json` 保存 `memory.mode: custom` 与目录；
  - `/memory` 状态显示 `custom-memory`，读到 1 条；
  - 设置页截图可见「已接上：custom-memory（1 条）」。

## 资源导入

在同一个真实 DSH Web 主机上通过页面同源请求调用设置页使用的同一个 `/assets/import`：

- layered 皮肤目录导入 `<数据根>/skin/layered/demo-skin/`；
- 共享音效导入 `<数据根>/assets/sound/click.wav`；
- 会话鱼图片导入 `<数据根>/assets/session-fish/fish.png`；
- `GET /skin/main/resources` 的 `layered.available` 出现 `demo-skin`。

结果均为 `ok:true`，三个目标文件均存在。native 文件选择框没有做 OS 级自动点击；
导入按钮使用的同一宿主 API 已在真实 DSH 主机上走通。
