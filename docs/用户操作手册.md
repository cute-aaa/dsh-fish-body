# dsh-fish-body 用户操作手册

> 面向第一次安装和使用本插件的用户。目标是：安装后只通过 DSH 设置页完成日常配置、素材导入、soul / memory 项目接入，不再修改插件或另一侧项目的代码。

## 1. 安装前确认

需要：

- DeepSeek Harness（DSH）桌面应用或 `dsh web`；
- 命令行安装时准备 Node.js ≥ 22.12；
- 建议先关闭正在运行的 DSH 界面再安装插件，避免宿主进程仍持有旧插件。

查看版本：

```sh
node -v
dsh --version
```

## 2. 安装

### 方式一：应用内插件管理

打开 DSH 的「插件管理」，在安装框填 `dsh-fish-body`，按提示安装，然后重开 DSH。

### 方式二：命令行

```sh
# dsh web
dsh plugin --profile web add dsh-fish-body

# DSH 桌面应用
dsh plugin --profile desktop add dsh-fish-body
```

> `dsh plugin --profile web ...` 可能触发宿主的 web 清理 preflight，关闭当前 web 实例。执行前先保存工作，安装完成后重新打开。

### 方式三：本地 tarball / Release

npm 包尚未发布时，使用 Release 里的 `.tgz`；版本号按实际下载文件替换：

```sh
dsh plugin --profile desktop add https://github.com/cute-aaa/dsh-fish-body/releases/download/v0.6.1/dsh-fish-body-0.6.1.tgz
```

### 方式四：源码安装

```sh
git clone https://github.com/cute-aaa/dsh-fish-body.git
cd dsh-fish-body/dsh-fish-body
npm install
npm run build
dsh plugin --profile desktop add file:/absolute/path/to/dsh-fish-body/dsh-fish-body
```

`npm run build` 会生成 `lib/`、桌面共享核心和类型声明；只跑 `tsdown` 不够。

## 3. 第一次启动

安装后重新打开 DSH。默认宠物会出现在右上角。

打开设置页后，六个分区分别是：

| 分区       | 主要用途                                   |
| ---------- | ------------------------------------------ |
| 桌宠       | 选择宠物、名字、头像、角色人设             |
| 外观与手感 | 渲染方式、皮肤、位置、尺寸、物理参数       |
| 声音       | 音效、语音合成、语音输入                   |
| 对话       | 对话模型、图片、动作联动、历史轮数         |
| 会话鱼     | 会话鱼的开关、皮肤、大小和播报             |
| 系统       | 素材与字体、兼容与记忆、文件目录、维护动作 |

## 4. 资源导入

### 4.1 在线素材包

进入「系统 → 素材与字体」：

- 「下载」从清单地址获取；
- 「本地 ZIP」从本机选择压缩包；
- 「本地目录」直接选择一个已经解压的目录；
- 「删除」移除已安装版本。

Dymon 手写体随插件包分发（OFL-1.1）；表情包、额外动画和 Live2D Cubism Core 走按需获取。下载/安装前先看许可徽标。

### 4.2 字体和表情包

- 字体：Dymon 手写体已随包提供；当前版本不会自动列出 `<数据根>/fonts/` 里的其它字体，其它下拉项是系统字体预设。
- 表情包：放进 `<数据根>/assets/memes/`；
- 已安装素材包的查找顺序是「用户目录 → 资源包 → 包内默认」。

### 4.3 主宠物皮肤

进入「外观与手感 → 皮肤目录」：

- layered：选择包含 `manifest.json` 的皮肤目录；
- live2d：选择包含 `*.model3.json` 的模型目录；
- webm：选择 `.webm` 动画文件。

导入后点「重新扫描」，再到「渲染方式 / 模型」下拉里选择新资源。同名资源默认不覆盖；需要替换时先删除旧目录。

Live2D 还需要单独安装 Cubism Core。完整步骤、目录结构、排障和出版许可说明见
[Live2D 安装指南](Live2D安装.md)。

### 4.4 音效

进入「声音」：

- 卡头「导入共享音效」：放到用户共享音效目录；
- 槽位明细里的「导入」：按当前皮肤 / 渲染方式自动算目标文件名；
- hook 行里的「导入」：生成 `hook-<名字>.<扩展名>`；
- 「打开文件夹」和「试听」仍可用于排障。

支持 `.wav` / `.ogg` / `.mp3` / `.m4a`。没有命中文件时，卡片会显示实际路径和“建议放这里”的目录。

### 4.5 会话鱼皮肤

进入「会话鱼 → 皮肤」，点「导入皮肤」选择图片、GIF、webm 或 mp4；导入后会自动重扫。

## 5. 接入 soul 项目

### 5.1 内置来源

进入「桌宠 → 角色」，来源下拉可选择：

| 来源            | 产物                                                                        |
| --------------- | --------------------------------------------------------------------------- |
| `dsh-fish-soul` | `persona.json`（SillyTavern v2）                                            |
| `dsh-soul`      | `SOUL.md` / `IDENTITY.md` / `AGENTS.md` / `HEARTBEAT.md` 等 Markdown 文档族 |
| `surfcore`      | 它自己 `character.json` 里的 persona 自述路径                               |
| `Coopanion`     | 工作区里的 `PARTNER.md`                                                     |
| 自定义路径      | 用户指定的 JSON / PNG 卡或 Markdown 文件/目录                               |

### 5.2 扫描并应用

1. 选择来源；
2. 点「扫描并导入」；
3. 在角色下拉里选择角色；
4. 点「应用到此宠物」；
5. 勾选「同时改名字」时，名字也会跟着角色名。

扫描只写全局角色库；只有「应用」才会改当前宠物的人设。文件宠物（pet pack 实例）的人设由所属种类管理，应用按钮会置灰。

### 5.3 自定义路径

选择「自定义路径」后：

1. 选一个 JSON / PNG / Markdown 文件，或选一个目录；
2. 点「保存并扫描」；
3. 如果路径在数据根 / `DSH_HOME` 之外，会出现授权提示；
4. 确认后路径保存到 `config/integrations.json`，下次打开设置页仍然有效。

外部路径只会读取用户确认过的那一条路径；路径移动或删除后，设置页会显示缺失并允许重新选择。

### 5.4 文档导入

没有标准角色卡时，用「导入文档」：

- 支持 `.md` / `.txt` / `.json` / `.png` / `.docx`；
- 先预览，编辑名字 / 描述 / 性格；
- 点「导入角色库」才落盘；
- `.bin`、`.doc` 等不支持格式会给出明确原因。

## 6. 接入 memory 项目

进入「系统 → 兼容与记忆」。

### 自动检测

- `dsh-rofm`：优先读 `<DSH_HOME>/dsh-rofm/memory/`；
- `dsh-suzu-memory`：读 `<DSH_HOME>/dsh-suzu-memory/`；
- 只支持 md / txt / 结构像记忆的 json；
- 卡片会显示接上了谁、读到几条、跳过了几条。

### 自定义目录

1. 点「自定义目录」；
2. 选目录或手输绝对路径；
3. 点「保存并重连」；
4. 外部目录需要确认读取授权；
5. 想恢复自动检测，点「自动检测」。

记忆后端是单槽：如果已被其它实现占用，本插件只报告「槽被占用」，不会覆盖别人的实现。

## 7. 语音

进入「声音 → 语音接入」：

- 本地 GSV：填 GPT-SoVITS `api_v2` 地址和音色包目录；
- 「导入音色」：选择权重目录、参考音频和文本，预检后批量落盘；
- 在线 edge：免费回退链的一部分；
- DeepSeek 云端 TTS：默认关闭，按字符计费，失败会回落免费链。

云端密钥放在 DSH 凭据库，不写进 `voice-providers.json`。

桌宠会从运行时语音状态里知道自己接了哪些 TTS、当前音色是什么、哪些实现暂时不可用，
因此被问“你用什么声音”时应按实际状态回答。它不能自行切音色，也不能按句指定 provider。
TTS 只生成说话；可以让它念歌词或做有节奏的朗读，但不会生成歌曲旋律，不应宣称能真正唱歌。

当前版本未内置 Drama3 Studio 本地语音 provider。Drama3 更适合作为后续“高级本地配音”
选项，需要额外的参考录音、模型与硬件配置；不要按 OpenAI TTS 的方式直接填 Studio 地址。
与 GSV 的差异和后续接入条件见 [Drama3 支持评估](Drama3支持评估.md)。

## 8. 备份、升级、回滚和卸载

### 备份

设置页「系统 → 备份与恢复」可导出设置快照；命令行也可以：

```sh
npm run rollback -- snapshot --label before-upgrade
```

### 升级

先备份，再重新安装新版本，最后重开 DSH。源码安装需要重新 `npm run build`。

### 回滚

```sh
npm run rollback -- list
npm run rollback -- restore <id>
npm run rollback -- restore <id> --apply
```

默认是干跑；确认覆盖路径后再加 `--apply`。

### 卸载

```sh
dsh plugin --profile desktop remove dsh-fish-body
```

卸载插件不会删除数据根。要彻底重来，先打开「系统 → 文件与目录」确认路径，再手动删除整个 `<数据根>`。

## 9. 数据目录

常见布局：

```text
<数据根>/
├─ config/        main-config.jsonc / session-fish.json / voice-providers.json / integrations.json
├─ data/          memory.json / todos.json / persona-characters/
├─ cache/         可重建缓存
├─ runtime/       Electron 运行时
├─ skin/          用户皮肤（layered / live2d / webm / sound）
└─ assets/        共享动画、音效、表情包、皮肤池、会话鱼
```

设置页「系统 → 文件与目录」是路径真源；不要根据旧版文档猜 `dsh-pet/` 或 `pet/` 路径。

## 10. 常见问题

| 现象                 | 先检查                                                                              |
| -------------------- | ----------------------------------------------------------------------------------- |
| 安装后没出现宠物     | 是否重开 DSH；插件管理里是否显示已启用；设置里宠物 display 是否为 none              |
| 皮肤导入后下拉没有   | 是否点了「重新扫描」；layered 是否有 `manifest.json`；live2d 是否有 `*.model3.json` |
| Live2D 选项置灰      | 按 [Live2D 安装指南](Live2D安装.md) 检查 `<数据根>/cubism/live2dcubismcore.min.js`  |
| 音效没有响           | 看音效明细的实际路径与建议落点；检查总闸、槽位开关和音量                            |
| soul 来源置灰        | 打开来源提示看约定目录；或改用「自定义路径」                                        |
| memory 显示槽被占用  | 另一个记忆实现已注册单槽；先停用其中一个，本插件不会抢占                            |
| 外部路径保存失败     | 路径必须绝对、存在，并且用户确认过外部读取授权                                      |
| 本地素材包安装失败   | 包 id 必须在清单里；zip/目录内容要完整；同名包先删除旧版本                          |
| 删除或移动路径后报错 | 设置页会显示缺失；重新选择路径或恢复自动检测                                        |

## 11. 安全与许可

- 插件只监听本机回环地址；所有私有接口需要本进程令牌。
- 外部 persona / memory 路径必须显式授权；路径经过 realpath 边界校验。
- 素材包下载会校验字节数与 sha256；安装先落临时目录再原子换名。
- 代码是 MIT；素材与第三方组件有各自许可，详见根目录 `LICENSE`、`NOTICE` 和素材包上的许可徽标。
