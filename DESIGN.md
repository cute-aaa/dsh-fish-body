## 二、状态真源规则（多入口字段的通用约束）

1. **一个状态一个出口**：任何「多个入口能改同一状态」的字段，写路径必须收敛到一个函数（如 `windows.setClickThrough` / `windows.setHidden`），其余入口只调用它。
2. **出口内判变化再广播**：`prev !== value`（首次登记 `undefined` 也算变化）；同值重复设置不广播，但**仍回推渲染端**以纠正漂移。
3. **展示端不存状态**：托盘菜单、右键菜单的勾选一律**现算**（运行期真值优先，窗口不在才回落配置）。
4. **订阅端合并刷新**：在飞时置 `again`，结束后 drain；不要逐次重画，也不要"只补一次"（会丢最后一次变更）。
5. **不新增并行频道**：同一件事不要第二条 IPC 通道或第二个 HTTP 端点；渲染端已有频道保持不变。

## 三、变更前检查清单（改代码前逐条对）

- [ ] 这次改动会不会**新增一个入口**去改已有状态？如果是 → 必须先落到单一出口，再让新入口调它（否则会重演「托盘显示反了」这类缺陷）。
- [ ] 有没有**新增配置字段**？→ 三处必扩：`shared/types.ts`、`host/config/merge.ts`、`host/config/save.ts` 的实例白名单重建（漏一处就会被下一次保存静默丢掉）。
- [ ] 有没有**新增 HTTP 端点或改响应形状**？→ `openapi.yaml` 双向校验（`npm run check:openapi`），并在本文件第一节与 `03-code/api-docs.md`（若走 DevFlow）登记。
- [ ] 有没有**改失败语义**？→ 本仓业务失败是 `200 + {ok:false,reason}`，`400` 只留给非法 JSON；不要在客户端按 4xx 写断言。
- [ ] 有没有**「点按钮 → 选文件/目录/行 → 回填输入框或勾选」的链路**？→ 选中回调必须直接写单一状态源（不依赖渲染期闭包里的临时 id），取消不动值，`unsupported` 给可操作提示；并且补一条装配层或 UI 层断言（`npm test` / `npm run test:ui` 里能跑的那种，不靠人工点）。
- [ ] 有没有**「点按钮 → 等用户 / 等外部」的链路**？→ **不得以时间为条件判失败**：不许用 `setTimeout` / `AbortController` 超时去判「弹不出来」。必须写清**谁释放什么**（子进程 `close`、连接 `close`、调用方的 `signal`），并让「用户在框里待 10 分钟」这种正常情形保持 pending。排障用的心跳只能写日志，**不能参与结局**（`/pick-file`、`/pick-folder` 是这条规则的参考实现）。
- [ ] 有没有**改渲染/皮肤目录语义**？→ `count` 只数本行目录、回落单列、下拉用 `available`；用户目录优先，包内 `assets/pet` 只回落（用户放同名皮肤时用户那份生效，见 `appendPackagePoolRoot`）。
- [ ] 有没有**改云端语音四轴/预设**？→ 检查 `baseURL` 三态、手填保护、`needsKey` 是否要认 `useCloud`、以及「非 deepseek 预设不得复用宿主 key」。
- [ ] 有没有**碰多工作树**？→ 先做 `AGENTS.md` 的「开工前三步」，确认主检出没有未合并/未提交的同面改动。
- [ ] 改了 UI 文案？→ 8 份字典键集与占位符一致（`locales/index.test.ts`）；提示文案不能承诺行为没做到的事。
- [ ] 有没有**把共享 CSS 常量拼进新的注入器，或从某选择器移走布局规则**？→ 依赖的基类必须随常量走（例如 `PANEL_CSS = TIP_BASE_CSS + 面板样式`），并在消费侧断言 `startsWith(基类)`；新增注入点必须自带基类。缺基类的失效形态是「气泡落进文档流、常驻并截获点击」，不是样式瑕疵。

## 四、可执行门禁

```bash
cd dsh-fish-body
npm run check:design     # 本文件与代码/契约的对齐校验
```

它做三件事：

1. **入口覆盖**：从仓库根 `openapi.yaml` 提取 `/dsh-pet-7340/<前缀>` 的全部前缀，要求本文件第一节「入口」列里都出现过（新增端点却不在 DESIGN.md 登记 → 失败）；
2. **owner 文件存在**：第一节表格里出现的 `path/to/file.ts` 形式引用必须真实存在（文件改名/删除却忘记更新文档 → 失败）；
3. **必备小节**：本文件必须包含「能力清单」「状态真源规则」「变更前检查清单」「可执行门禁」四节。

与其它门禁一起跑（提交前）：`npm test`、`npx tsc --noEmit`、`npx tsc -p tsconfig.test.json`、`npm run lint`、`npm run format:check`、`npm run check:cycles`、`npm run check:openapi`、`npm run check:design`、`npm run test:ui`（碰 UI 时）、`npx tsdown`。

## 五、稳定兼容面（不可随便改的对外标识）

这些名字出现在**用户已有的配置、数据目录、第三方脚本或本机进程参数**里。改它们不会让测试变红，但会让老用户的东西当场失效（配置读不到、皮肤消失、脚本调不通），而且是**静默**失效——所以列成一张表，改名之前先对照：

| 标识             | 值                                          | 为什么不能改                                                                        |
| ---------------- | ------------------------------------------- | ----------------------------------------------------------------------------------- |
| 插件路由前缀     | `/dsh-pet-7340`                             | 浏览器端、桌面 Helper、第三方探针（`tools/cordis-probe`）都按它拼 URL；改了就全 404 |
| 请求头           | `X-DSH-Pet-Token`                           | 桌面壳与页面之间用它做本机鉴权                                                      |
| 环境变量前缀     | `DSH_PET_*`（37 个）                        | 用户的启动脚本、CI、冒烟脚本已经在用                                                |
| 数据根           | `<DSH_HOME>/fish-body`                      | 用户配置、皮肤、记忆都在这里                                                        |
| 旧数据根         | `<DSH_HOME>/dsh-pet`                        | 仍会被读取并在启动时迁移；删掉兼容分支等于让老用户丢配置                            |
| 样式去重标记     | `data-plugin-css="dsh-pet/<file>"`          | 重复挂载靠它判重，改名会重复注入样式                                                |
| localStorage 键  | `dsh-pet/settings-pet`、`dsh-pet/pick-dirs` | 用户的选择记忆，改名即清空                                                          |
| 设置备份 kind    | `dsh-pet/settings-backup`                   | 旧备份文件的识别字段，改名后认不出老备份                                            |
| 独立模式命令     | `dsh-pet-standalone`                        | 文档与用户脚本里的命令名                                                            |
| 独立模式默认端口 | `3080`                                      | 与 DSH web 实例的约定，改了两者会抢端口                                             |

新增同类标识（又一个 localStorage 键、又一个环境变量）时，**先在这张表里补一行**再动手；这张表本身不做自动校验，靠评审看。
